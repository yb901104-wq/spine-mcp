# 2026-11-03

## 官方 JSON 文档对照与 curve 维数缺陷（重大发现）

用户提供 [Spine JSON 格式文档](https://zh.esotericsoftware.com/spine-json-format) 作为参考。用户判断：一份文档无法覆盖所有版本，版本间细节差异正常。**该判断成立，已实测确认。**

### 1. 该中文文档是 3.8 口径，与 4.1.24 有硬冲突（项目实现均正确，未盲信文档）

| 项 | 官方中文文档 | 4.1.24 runtime 实际 | 项目 |
|---|---|---|---|
| rotate 关键帧字段 | `angle` | `value`（SkeletonJson.js:972 `getValue(keyMap,"value",…)`；:623 rotate→readTimeline1） | ✅ 用 value |
| 绘制顺序 timeline 名 | `draworder`（全小写） | `map.drawOrder`（:892） | ✅ 用驼峰 |
| curve X 轴单位 | 「单位是帧」 | cx 为 0..1 归一化（readCurve 里 cx 不乘 scale，cy 才乘） | — |

结论：官方文档只能作**字段语义参考**，不能作**写入校验依据**；真正依据是 4.1 runtime 源码 + 当前版本真实样本。项目 `docs/官方JSON规范审查.md` 里「官方文档字段含义 + 4.1.24 样本字段形态双重规则，差异必须记录」的策略是对的。

### 2. 真正的缺陷：curve 在二维 timeline 上必须是 8 元，官方文档完全没写

- runtime `readCurve(curve, …)` 内 `let i = value << 2;` —— `value` 是**维度索引**，二维 timeline 第二维度从 `curve[4]` 起取。
- 实测样本 `xiaoren.json`：rotate 的 curve 恒为 **4 元**，translate/scale/shear 恒为 **8 元**（前 4 给 x、后 4 给 y）。
- 实测后果（bone2 translate，6 个 8 元 curve 截成 4 元）：**41 帧中 40 帧 y 值为 NaN，x 值完全正常、无任何报错**。属静默污染，x 分量正常极具迷惑性。

### 3. 项目侧缺口

`src/spineJson.ts:1883-1886` `validateCurve` 只校验 `length >= 4 && length % 2 === 0 && 全部有限`，**未按 timeline 维度区分**，故 translate 传 4 元 curve 会通过审查。
缓解因素：项目规则「Agent 凭空生成新动画时默认不写 curve」，实际路径已规避；风险点在于 `spine_set_bone_keyframe` / `spine_apply_pose_keyframes` / `spine_apply_pose_sequence` 的 `curve` 参数允许 Agent 自由传值。

### 4. 建议（待用户确认后实施，改前须同步 docs/官方JSON规范审查.md）

`validateCurve` 增加维度规则：rotate → 4 元；translate/scale/shear → 8 元；不足则报 error 而非放行。

## 实施结果（用户已批准，同日完成）

**代码改动 `src/spineJson.ts`**：
- 新增 `BONE_CURVE_LENGTH = { rotate:4, translate:8, scale:8, shear:8 }` 与 `expectedBoneCurveLength()`。
- `validateCurve(pathBase, curve, index, issues, targetType?, timeline?)` 加维度分支：bone timeline 严格等长，非 bone（slot/drawOrder）沿用原「≥4 偶数」规则。调用点两处已分别传 `spec.targetType/spec.timeline` 与 `targetTypeFromTimelinePath(pathBase)/timeline`。
- `assertCurveValue(curve, boneTimelines[])` 支持维度；新增 `collectPoseBoneTimelines()`，pose 级按实际涉及的 timeline 集合校验，集合含多个不同维度需求时直接拒绝（不自动补全控制点）。
- `setBoneKeyframe`、`setCurve` 入口补 `assertCurveValue(args.curve, [args.timeline])`。
- 错误统一抛 `ToolError('VALIDATION_FAILED', …)`（原先抛普通 Error 会被 toolError 的「必须」关键词启发式误判成 `MISSING_INPUT`）。

**文档同步**：`docs/官方JSON规范审查.md` 新增「2026-11-03：curve 控制点数组必须匹配 timeline 维度」节 + 规范来源补中文文档（3.8 口径）与 runtime 依据；`docs/MCP操作清单.md` 顶部加 2026-11-03 补注（未增删工具，仅加强入参校验）。

**测试**：`test/spineJson.test.ts` 新增维度规则用例；原「apply pose sequence creates a closed animation」里 pose 级 `curve:[0.25,0,0.75,1]` 同时覆盖 rotate+translate 属被修复的缺陷行为，已改为 `"stepped"`。

**验证结果**：
- `npm run build` 通过。
- `test/spineJson.test.ts` 单跑 **45/45 通过**（需先清残留锁）。
- curve 相关 4 个文件（motionEngine / poseWorkflow / hostAnimationCandidate / legacyRegression）**29 pass / 0 fail**。
- MCP stdio 端到端实测：translate+4元→拒、translate+8元→放行、rotate+8元→拒、rotate+4元→放行、set_curve 4元→拒、pose 混合+4元→拒、stepped→放行，错误码 8 处全部 `VALIDATION_FAILED`。

**环境坑（与代码无关，记录备查）**：
1. 残留 `writer.lock` 会让写入类测试报「已有写入者或锁状态不明」；须先用 `process.kill(pid,0)` 确认 PID 死亡，再用 `recoverDeadWriter()` 回收，不要手删。
2. 残留 file lock（`.spine-mcp/locks/*.lock`）会让单个测试报「角色文件正在被其他任务修改」。
3. **全量 `npm test` 会稳定失败 25 项**，全部是 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`（单轮累计删除超阈值 50，触发宿主删除守卫），集中在 `spineJson.test.ts` 的 `beforeEach` 反复 `rm(test-output)`。项目侧无法配置该阈值，**改以分文件跑为准**。昨日日志的「干净轮」口径不再复现，勿据此判断回归。
