
## 工单拆分：宿主（Host）独立成单

- 新建 `docs/plans/host-evolution.md`（宿主工单 v1）：先定义主体（Document Store / Session / Writer / Presenter），核心原则 **写入者不判定、判定者不写入**；两种模式 detached（默认，MCP 直写）/ attached（Host 持有写入与真相）；B 观察 → C 会话与写入 → D 求解宿主（spike 判据，不承诺）。
- 契约表唯一一份在 HOST §3（端点 / 工具 / Session 字段 / 错误码：HOST_UNAVAILABLE、REVISION_CONFLICT、WRITE_FORBIDDEN、TARGET_DRIFT、CAPTURE_UNVERIFIED）。
- ADR-1..5：唯一写入者、真相归属、双模式部署、判定权留 MCP、求解暂留 MCP。
- `docs/plans/mcp-l1-l2.md`（由 plans 目录复制并升 v1.1）：L2.4/L2.5 收敛为指针；批次表改为 L1/L2 批 1–3（全部可无宿主验收），宿主相关标为 HOST-B/C/D；自审表 5 行改指 HOST。
- 拆分的理由：宿主要求和 L1/L2 有两处天然重叠（session、preview 契约），双份会重演 bodyView 自证；因此契约只留一份，另一份只写指针。

## 宿主工单升 v1.1（独立审查后修订）

- 补最关键的 §4.5 状态同步决策：实时用 node canvas（`/api/frame`，5–50ms、0 token），验收用真 player（`/api/capture` + 临时 live JSON 重载）；**否决 WS 推骨架**，因为它会让页面运行态变成第三个真相（ADR-6）。
- 黄金帧从"可选"升级为 C 的前置条件（canvas 与 player diff ≤0.5%，否则 canvas 图标 advisory 且 review 拒收）。
- 补 §4.6 认证与端口发现：`.spine-mcp/host-port.json`（0600，含 pid/port/token/apiVersion）+ 所有 POST 校验 `X-Spine-Host-Token` + Origin 限本机（ADR-8）。
- 补 §5.1 op 语法（5 类 op + 6 条约束 + diff 形式 [{path,before,after}]），§5.2 journal vs 磁盘裁决（磁盘赢、journal 归档 rejected），§5.3 undo 仅未提交且按 clientId 分桶（ADR-7）。
- 修 D 阶段判据：改成"端到端 patch→frame 可见 P95>300ms 且 solve 占比>50%"，原判据在 C 方案下永远不成立。
- 补 §11 token 预算（digest 200–400 / 480² 图 350–500 / 960² 1.2–1.5k / 整份 JSON 禁止）、§12 性能预算、故障注入测试、双渲染器与临时文件风险、错误码 4 个新增。
- L1/L2 工单的指针同步补 `/api/frame` 与 C/A 决策。

## 宿主工单升 v1.2（强制 pin + 13 条契约修边界）

- 决策：target 采用**强制 pin**（ADR-9）。未 pin 时 patch/commit/undo/redo 一律 `TARGET_NOT_PINNED`；提供 `spine_host_pin{posePath,force?}`；Host 重启不恢复 pin，避免“以为改 A 实际改 B”。
- 契约修补：capture 增 `revision` 并绑定 manifest；frame revision 不符返回 409（不返回旧帧）；commit 到新 outputPath 时 `pinned=false` + activeDoc 切换 + revision 归零。
- 安全：所有带路径的 GET 走 `resolveWorkspacePath` + realpath 祖先校验 → `PATH_FORBIDDEN`；projectId 必须已登记；页面 token 改为 Host 注入 `<meta>`（不走 query/localStorage）。
- 平台：Windows 的 0600 无效，改 icacls；失败降级 token-only 并在 `/api/state` 回 `security.mode`。
- 生命周期：单实例锁（pid 存活则复用端口文件）；`ensurePreview()` 的 spawn 规则（`SPINE_HOST_AUTOSTART=0` 可禁用、cwd=installRoot、日志落 `.spine-mcp/host.log`、100/300/900ms 退避）。
- 文档模型：定义 doc kind（skeleton/pose/motion）+ **per-doc revision** + `session.activeDoc`；op 与 kind 不匹配报 `DOC_NOT_LOADED`。
- 其他：D 判据与预算对齐（>200ms ≈ 120ms×1.6）；live 文件 TTL 24h + 启动清理 + commit 拒绝前缀；SSE 心跳/Last-Event-ID/resync；测试矩阵加路径越权、token 下发、capture 竞态、live 清理。

## 宿主工单升 v1.3（寻址统一 activeDoc + 12 条修补）

- **ADR-10 统一寻址**：frame/capture/patch/commit/undo 一律作用于 `activeDoc`，不再接受 posePath；换文件必须 `open`。代价是"旁观另一份"要显式 open，收益是消灭"改 A 看 B"。
- 补 `POST /api/open` + `spine_host_open`（C 的入口）：建立 activeDoc、清空 target/pinned、返回 kind/revision/fileHash。
- 工具表补齐 `spine_host_redo`、`spine_host_pin`；写工具定死为 4 个（patch/commit/undo/redo），pin/open 属绑定操作。
- `/api/frame` 渲染源定死为 `pose.solution`（B 不求解）；缺失 → 新码 `NO_SOLUTION`；bounds 取 visualRig calibration，同角色固定，保证两帧可比。
- **drift 拆两级**（ADR-12）：Host 只判 fileHash → `TARGET_STALE`；语义指纹由 MCP 判 → `TARGET_DRIFT`。原设计要 Host 判语义指纹，但 §1.4 明确指纹策略归 MCP，逻辑冲突。
- **journal 按 doc 分文件**（ADR-11）：`.spine-mcp/journals/<sha1(docPath)>.jsonl`，header 带 docPath/lastCommittedHash/lastCommittedRevision，杜绝切文档后跨 doc 重放。
- 端点优先级 `SPINE_HOST_ENDPOINT` > 端口文件；spawn 注入 `SPINE_MCP_WORKSPACE`，工程切换需重启 Host（不允许一个 Host 服务两个工程）。
- `index.html` 强制 no-store（否则缓存旧 token）；`security.mode` 收进 session；单实例锁改为 pid+startedAt+端口探活三合一。
- commit 到新 outputPath：revision 与 lastCommittedRevision 一起归零、栈清空。
- D 判据补注意：B/C 阶段 patch 不触发求解，frame 渲染 solution 快照，因此"占比"判据需先定义 patch→solve→frame 是否合并调用。

## 宿主工单升 v1.4（四轮审查收敛）

- **#1 B1 增交付 `applySolution`**：核代码确认全仓没有"把 solution.bones 回放回 skeleton"的函数（rasterFrame 需要已摆好的 skeleton，唯一得到方式是重新求解）。因此 B"只渲染不求解"缺实现，v1.4 把它写成 B1 第 1 项，并要求单测与重新求解关节坐标 <1e-6。
- **#2 detached 镜像（ADR-13）**：统一到 activeDoc 后，无宿主时由 MCP 侧记录镜像，`spine_host_open` 返回 `mode:'mirror'`，后续工具照常寻址；镜像不持久、每次比对 fileHash。
- **#3 capture 前置**：player 只认 spine JSON，pose/motion 必须先 live 导出并标 `exported:true`。
- 其余：`target.docPath` 改名、`open` 依赖解析 + `DOC_INCOMPLETE`、乐观锁加 `sessionId` epoch、capture viewport 只接受记录值否则 advisory、commit 到新路径初始化新 journal header、`security.mode` 明确 token 恒必填、`/api/frame` 20/s 限流、验收按阶段标工具数。
- **#8 黄金帧定案（ADR-14）**：默认 D——人工产出 3 张 player 基线 PNG + manifest 提交到 `test/golden/`，CI 只重渲 canvas 侧比对；player 版本变则 fail 要求重出；A（playwright 脚本）作可选本地工具，不进 CI。
- 结论：契约矛盾已清零，剩余为"实现前提"，B1 可开工。

## 宿主工单升 v1.5（第五轮审查的边界补丁，未施工）

- 补 `/api/shutdown`（工程切换用，202、先 flush journal、幂等）。
- **B1 缩小范围**：frame 只支持 pose；skeleton/motion → 新码 `UNSUPPORTED_DOC_KIND`，motion 留 B2。
- `SPINE_HOST_ENDPOINT` 模式必须同时给 `SPINE_HOST_TOKEN`，缺 token 直接判不可用（不回落端口文件，避免连错实例）。
- `/api/open` 幂等语义：同路径保留 revision/target/pinned 并回 `reopened:true`；不同路径才清空。
- journal header 的 `sessionId` 仅审计不校验（否则重启后 journal 全被判废）。
- `REVISION_CONFLICT` 加 `detail.reason: stale|epoch`。
- `goldenPassed` 三态边界写死：未跑=unverified、跑失败=false、版本变=fail 并要求重出基线。
- frame `size` 上限 480（960 只给 capture），与 token 预算对齐。
- `applySolution` 初版容差放宽到 1e-4，稳定后再收 1e-6。
- detached 的 `preview_state` 形状改为 `available:false, mode:'mirror', activeDoc`。
- 结论：五轮后架构稳定，剩余为施工细节；用户决定暂不施工。
