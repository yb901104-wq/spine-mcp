# 以关节、骨骼和切片对应关系驱动姿态

## 本轮实现

参考节点、目标视觉锚点、实际附件顶点、关系比较与写入门禁已连接。骨骼原点只作为求解节点，不再自动当作可确认的视觉关节。

新增 MCP 工具：

| 工具 | 必需输入 | 输出与限制 |
|---|---|---|
| `spine_calibrate_visual_rig` | `filePath,mappingPath,visualRigPath` | 原点与实际切片影响候选；可传 `nodes,segments` 校准；输出全图、节点图、切片分解图和 manifest |
| `spine_review_visual_rig` | `visualRigPath,decision,reviewedBy,reason` | 确认校准节点与图像证据；未校准候选不能批准 |
| `spine_retarget_reference_pose` | `referencePosePath,visualRigPath,standardPosePath,posePath,correspondence` | 从两段方向、目标链长及支撑关系生成单姿态；冲突返回 `ok:false`，只保存诊断草稿 |
| `spine_compare_pose_graphs` | `posePath` | 从实际求解结果回读；传 `candidatePath,animation,time` 可复核真正动画 |

所有接口支持 `projectId`，路径受登记工作区约束，默认 `dryRun:true`。默认只返回关节与附件摘要，完整权重、顶点保存在报告；需要时使用 `detailed:true`。工作流产物与角色动画写入分开；这些工具不会修改角色 JSON。

## visualRig 数据

独立文件记录 `filePath,mappingPath,skin,sourceFingerprint,nodes,segments`。

```json
{
  "nodes": {
    "leftWrist": {
      "type": "boneLocal", "bone": "手骨骼",
      "point": [0, 2], "calibrated": true,
      "basis": "按手部切片近端与前臂接缝校准", "confidence": 0.8
    },
    "head": {
      "type": "meshTriangle", "slot": "头部插槽",
      "attachment": "头部附件", "triangle": 0,
      "weights": [0.2, 0.3, 0.5], "calibrated": true,
      "basis": "按实际网格三角形内的头部中心校准"
    }
  },
  "segments": {
    "leftArm.1": {
      "nodes": ["leftElbow", "leftWrist"],
      "bones": ["前臂骨骼", "手骨骼"],
      "attachments": [
        {"slot": "前臂插槽", "attachment": "前臂附件"},
        {"slot": "手插槽", "attachment": "手附件"}
      ]
    }
  }
}
```

完整文件必须包含 head/body、左右肩肘腕髋膝踝，以及八条四肢线段。三角形序号与重心权重通过实际 runtime 校验；加权顶点由官方 runtime 计算。附件影响从真实 region 绑定与 mesh 权重读取，不按名称猜测。校准图供 Agent 判断，不自动证明解剖位置正确；遮挡估计必须记录依据。

指纹绑定角色结构、mapping、skin、atlas 和页面纹理。增加无关动画不使绑定失效；修改附件、节点、贴图或 mapping 后须重新校准和审查。

## 参考与适配

参考沿用 `spine_create_reference_pose`，增加统一 `edges`、`support.left/right`、可选 `grip.points.left/right`、`grip.angle/basis` 和 `relations.frontGrip`。可见点与遮挡推测分别记录；未知必要点不能确认目标。

`correspondence` 必须明确提供：

```json
{
  "left": "right", "right": "left",
  "basis": "经过逐侧核对的对应依据",
  "anatomicalIdentity": "解剖身份依据及尚有的不确定性",
  "projectedOrder": "画面前后层对应"
}
```

不会按时间临时交换左右。标准站姿提供角色校准与默认手掌角度，四肢方向、弯曲方向和脚部目标均由参考节点重建。地面锁定采用鞋底至踝的实际偏移，不能直接把踝压到地面。可显式传入假想杆约束；约束冲突仍阻止确认。

## 比较与审查

固定策略见 `policies/pose-comparison.v1.json`。方向/屈曲 15°；站距、肩腕向量和握持间距归一化误差 0.15。支撑、伸臂方向、分腿关系和显式身前握持逐项检查，没有总分抵消。

伸臂前后关系只对超出中性区的投影进行分类：水平肩腕距离在臂长 0.15 内归为中性，避免垂直手臂的浮点噪声和微小比例差被当成反向伸臂。该规则随策略版本固定，调用者不能在失败后传参数放宽。

每项返回 `pass/fail/unverifiable`，包括参考值、实际值、误差、节点和不确定性。实际值来自校准视觉节点和附件，预期 IK 目标只用于诊断。干净图用于轮廓判断；诊断图显示实际节点、附件三角轮廓、失败节点红色高亮、预期目标方框以及适配预期十字。

参考任务的 `spine_review_pose` 增加 `comparisonPath,stageId,checkResults`。检查项为 `standingOrAction,silhouette,jointDirections,support,grip,occlusion,referenceDifferences`，每项均需 `status:pass` 与独立具体依据。缺失、过期或超差比较不能被 Agent 批准覆盖。motion 构建和姿态门禁再次核对阶段、报告与审查，拒绝重复统一审查文本。

完整动画审查会从候选 JSON 的实际关键时间再次比较；真实写入重新采样并核验比较指纹。`duration` 改变时按源/目标周期比例映射关键时间。`preview:false` 不能绕过此门禁。底层修改造成输入 hash 或候选指纹变化后，原提交 token 不能复用。

## 解剖持杖手、身体视角及切片遮挡检查

参考 observation.actionSemantics 支持 `version:1 / weaponHand:left|right / identityStatus:confirmed / anatomicalBasis / bodyView / bodyViewBasis / occlusion`。身体视角可为 `frontThreeQuarter`、`side`、`backThreeQuarter`，参考有不确定性时可用 `sideOrBackThreeQuarter`。遮挡项保存 `{front,back,basis}`，语义部位可为 `body` 或已有肢体线段编号（如 `rightArm.1`）。缺少必要遮挡关系返回无法验证，不默认为通过。

`spine_calibrate_visual_rig` 增加 `anatomicalSides` 与 `viewProfiles`，均绑定确认指纹。解剖左右映射保持跨阶段稳定；视角配置保存实际附件状态、躯干插槽和看图校准依据。姿态 `frame.action.driver` 明确实际目标驱动手（如 `rightHand`），骨架比较独立输出 `action.weaponHand`、`action.bodyView`、`action.occlusion.*`。身体视角从 runtime 实际附件配置匹配已确认 profile；未经校准不能只传一个“背面”标签通过。遮挡用 runtime 绘制顺序回读。Agent 判断仍参与视角配置校准，这不是自动像素识别或数学上的视觉保证。

`frame.presentation` 支持受控 `attachments` 和完整 `drawOrder` 插槽排列，沿用 `spine_adjust_pose`、`spine_solve_pose` 和 v2 motion。显示状态在阶段边界离散切换，导出为已有 attachment/drawOrder 时间线；不改 setup、绑定、mesh、atlas 或 PNG。现有后发、面部显隐及背包层序可构造转身诊断候选，但不代表有完整三维转身模型。需要逐姿态查看轮廓并重新校准，不能自动批准隐藏五官后的身体视角。

中文验证：右手参考对应左手驱动必须失败；正面配置不能覆盖侧背参考；缺失视角/遮挡信息必须无法验证；同一附件状态不能标记成两种不同视角；遮挡层序反转必须失败。切片状态修改使配置匹配和旧审查失效。官方 runtime 回读 attachment/drawOrder 的阶段切换必须与单姿态一致。
