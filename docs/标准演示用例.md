# 标准演示用例

本文档记录一个固定的端到端演示剧本，用于验证 Agent、MCP 写入层、官方规范审查、备份、runtime 验证和 WinForms 观察平台是否能连成闭环。

演示目标不是证明动画已经达到最终美术质量，而是证明“自然语言请求 → Agent 制定计划 → MCP dryRun → 用户确认 → MCP 写入 → 验证流水线 → 预览观察”这条链路稳定可用。

## 演示目标

在 `example-json/skeleton-4.1.json` 中新建一个动画：

```text
demo-walk-loop
```

动画要求：

- 时长 `0.6` 秒。
- 首尾闭合，能够循环播放。
- 不复制或借用已有动画。
- 只写入 `/animations/demo-walk-loop`。
- 不修改 setup pose、bones、slots、skins、mesh/deform、constraints、events。
- 先 `dryRun:true`，用户确认后再 `dryRun:false`。
- 写入后执行 `spine_run_validation_pipeline`。
- 通过 `spine_preview_set_session` 让 WinForms 自动观察目标动画。

## 演示前准备

启动 WinForms 观察平台：

```bash
npm run observer
```

确认 Codex 已经连接 MCP，并让 Agent 执行握手：

```json
{
  "tool": "spine_agent_ping",
  "arguments": {
    "clientType": "codex",
    "agentName": "Codex"
  }
}
```

WinForms 的 Agent 连接状态应显示为绿色。

## 用户自然语言指令

第一句：

```text
给 example-json/skeleton-4.1.json 新建一个 demo-walk-loop 动画，做 0.6 秒循环走路动画，先 dryRun，不借用现有动画。
```

Agent 应先说明计划，再执行 MCP 工具。计划至少包含：

- 目标文件：`example-json/skeleton-4.1.json`
- 目标动画：`demo-walk-loop`
- 写入工具：`spine_apply_pose_sequence`
- 预计修改路径：`/animations/demo-walk-loop`
- 需要先查询：文档摘要、骨骼层级、必要时插槽或动画列表
- 安全策略：`dryRun:true`、传 `expectedHash`、检查官方规范审查和 diff 白名单

## 期望工具调用顺序

### 1. 查询文档摘要

```json
{
  "tool": "spine_get_document_summary",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json"
  }
}
```

验收点：

- `skeleton.spine` 为 `4.1.24`。
- `writable` 或等价字段表示当前版本允许写入。
- Agent 记录返回的 `hash`。

### 2. 查询骨骼层级

```json
{
  "tool": "spine_get_skeleton_hierarchy",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "includeSetupPose": true
  }
}
```

验收点：

- Agent 只选择真实存在的骨骼。
- 如果骨骼命名不直观，Agent 应先说明这是按现有骨架做的近似走路循环。

### 3. 执行 dryRun

Agent 使用 `spine_apply_pose_sequence` 一次事务写入多姿态序列。调用必须满足：

- `animation: "demo-walk-loop"`
- `duration: 0.6`
- `closeLoop: true`
- `overwrite: false`
- `dryRun: true`
- `expectedHash` 使用第 1 步读取到的 hash
- `poses` 包含 `time: 0`，并包含中间姿态，例如 `0.15`、`0.3`、`0.45`
- 不写入 `curve` 数组，除非有明确版本适配依据

dryRun 验收点：

- `summary.wroteFile` 为 `false`。
- `affectedPaths` 只包含 `/animations/demo-walk-loop` 下的路径。
- `operationValidation.ok` 为 `true`。
- `officialSpecValidation.ok` 为 `true`。
- diff 中没有 bones、slots、skins、events、constraints 等顶层结构修改。
- 如果目标动画已存在且未传 `overwrite:true`，工具应拒绝覆盖。

### 4. 设置观察会话

dryRun 后，Agent 调用：

```json
{
  "tool": "spine_preview_set_session",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "atlasPath": "example-json/xiaoren.atlas",
    "animation": "demo-walk-loop",
    "premultipliedAlpha": true,
    "mipmaps": false,
    "autoload": true,
    "operation": {
      "title": "演示：demo-walk-loop 走路循环",
      "status": "dryRun",
      "detail": "已完成 dryRun，等待用户确认写入。",
      "toolName": "spine_apply_pose_sequence"
    }
  }
}
```

验收点：

- WinForms 当前上下文显示目标 JSON、atlas 和动画名。
- 操作控制台显示当前是 dryRun。
- 此时因为文件尚未真实写入，预览可能找不到新动画，这是正常现象。

## 用户确认写入

第二句：

```text
写入，并执行验证流水线。
```

Agent 应重新读取文档摘要，拿到最新 `hash`，然后用与 dryRun 同一套 `poses` 调用：

```json
{
  "tool": "spine_apply_pose_sequence",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "animation": "demo-walk-loop",
    "overwrite": false,
    "duration": 0.6,
    "closeLoop": true,
    "dryRun": false,
    "expectedHash": "<最新hash>",
    "poses": "<与 dryRun 完全一致的姿态序列>"
  }
}
```

写入验收点：

- `summary.wroteFile` 为 `true`。
- 返回 `backupPath`。
- `operationValidation.ok` 为 `true`。
- `officialSpecValidation.ok` 为 `true`。
- 写入范围仍只在 `/animations/demo-walk-loop`。

## 写入后验证

写入后调用：

```json
{
  "tool": "spine_run_validation_pipeline",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "atlasPath": "example-json/xiaoren.atlas",
    "animation": "demo-walk-loop",
    "premultipliedAlpha": true,
    "mipmaps": false,
    "autoload": true
  }
}
```

验收点：

- `ok` 为 `true`。
- `structureValidation.ok` 为 `true`。
- `runtimeValidation.ok` 为 `true`。
- 返回可打开的 `previewUrl`。

然后调用 `spine_preview_set_session` 更新观察状态：

```json
{
  "tool": "spine_preview_set_session",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "atlasPath": "example-json/xiaoren.atlas",
    "animation": "demo-walk-loop",
    "premultipliedAlpha": true,
    "mipmaps": false,
    "autoload": true,
    "operation": {
      "title": "演示：demo-walk-loop 走路循环",
      "status": "validated",
      "detail": "已写入并通过结构校验与官方 runtime 加载验证。",
      "toolName": "spine_run_validation_pipeline"
    }
  }
}
```

WinForms 验收点：

- 预览区域载入 `demo-walk-loop`。
- 验证结果区域显示结构校验和 runtime 加载通过。
- 操作状态显示为已验证。

## Spine 软件导入验收

最后在 Spine 软件中导入：

```text
D:\AI_cc\spine-mcp\example-json\skeleton-4.1.json
```

验收点：

- Spine 不报“请选择一个有效的骨架 JSON 或二进制文件”。
- 动画列表里能看到 `demo-walk-loop`。
- 动画可以播放。

如果导入失败，不允许继续在错误 JSON 上修补。必须按 `docs/安全提交流程.md` 中的“导入失败恢复流程”恢复最近一次可导入备份，再重新制作。

## 回滚演示动画

如果演示结束后要移除 `demo-walk-loop`，也必须走 MCP：

```json
{
  "tool": "spine_delete_animation",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "animation": "demo-walk-loop",
    "confirm": true,
    "dryRun": true,
    "expectedHash": "<当前hash>"
  }
}
```

用户确认后再传 `dryRun:false`。删除同样会生成备份，并应再次执行 `spine_run_validation_pipeline`。

## 失败信号

以下情况表示演示没有通过：

- Agent 试图直接编辑 JSON 文件。
- Agent 使用多个单点写入工具连续提交完整新动画，而不是优先使用 `spine_apply_pose_sequence`。
- dryRun 没有传 `expectedHash`。
- diff 涉及 `/bones`、`/slots`、`/skins`、`/events`、`/constraints` 等路径。
- `officialSpecValidation.ok` 为 `false` 时仍继续写入。
- 写入后没有生成备份。
- runtime 验证失败后仍要求用户直接去 Spine 导入。
- Spine 导入失败后在错误 JSON 上继续修补。

## 演示完成标准

一次标准演示完成，需要同时满足：

- Agent 能理解自然语言并选择正确 MCP 工具组合。
- dryRun diff 合理，且没有越权路径。
- 真实写入生成备份。
- `spine_run_validation_pipeline` 通过。
- WinForms 能显示当前动画和验证结果。
- Spine 软件能导入修改后的 JSON。
