# 浏览器预览系统

## 姿态审查产物

同步 GIF 参考帧选择使用1微秒边界容差，避免 runtime float32 时长使事件边界错取上一帧。可通过从实际 GIF 解码的阶段采样图辅助检查；原速 GIF 和关键姿态仍分别保留。本次产物与分项验收见 [npc1姿态实例复验](npc1姿态实例复验.md)。

离线 MCP 渲染不依赖 Computer Use：参考原图/节点图先独立审查，再输出上参考下目标的 clean/diagnostic。固定缩放、裁剪、地面和目标联合相机；显式阶段时间含结束姿态，每页六列，可局部放大。完整动画同时检查同步 GIF 和目标原速 GIF。参考动画 WebP 保留真实帧延迟。图片与 manifest hash 作为审查证据；渲染成功不代表姿态正确。详见 [姿态校准与视觉审查](姿态校准与视觉审查.md)。

## Alpha 与 PMA

SpinePlayer 的 premultipliedAlpha 是混合模式开关，并不会把直通 Alpha PNG 自动预乘。浏览器预览通过 GET `/api/preview-alpha-assets?atlas=相对路径&pma=true` 读取 atlas 的每页 pma 标记（缺省 false），按目标混合模式生成内存纹理：直通转 PMA 时 RGB 乘 Alpha 并清除完全透明像素隐藏颜色，PMA 转直通时反向转换，格式匹配时原样使用。通过官方 Player 的 rawDataURIs 注入预览纹理，原 JSON/atlas/PNG 不改写。多页逐页处理，按贴图 hash 和两种 Alpha 模式缓存。切换预乘选项自动重新载入；状态栏显示实际转换页数。

NPC1 资源为直通 Alpha，原贴图有 18781 个带隐藏 RGB 的完全透明像素；旧页面用 PMA 混合原图时会出现白亮和紫绿色块。修复已在 Edge WebGL 实际页面截图验证，并覆盖预乘、反向转换、避免重复预乘、缓存与原文件保留测试。

项目首次预览不固定依赖开发示例路径：无已有会话时优先使用当前项目配套角色；未找到资源时保留空路径并提示选择。预览服务可达不表示 Agent MCP 已连接，连接状态独立判断。

本文档记录 Spine JSON MCP 的预览层方案。预览层只负责加载和显示动画结果，不负责写入 JSON；所有 JSON 修改仍必须通过 MCP 写工具、官方规范审查、diff 白名单和备份流程。

## 定位

当前项目核心仍是 TypeScript MCP server：

- MCP 负责读取、校验和修改 Spine JSON。
- 浏览器预览层负责用官方 Web runtime 加载 JSON、atlas 和贴图资源。
- 未来 WinForms 可以通过 WebView2 嵌入同一个预览页，不需要重写预览逻辑。

## 官方 runtime 版本规则

预览 runtime 的 `major.minor` 必须匹配 JSON 的 `skeleton.spine`：

- `4.1.24` JSON 应使用 `4.1.x` runtime。
- 不应假设 `4.3.x` WebComponents 可以加载 `4.1.x` JSON。
- 如果后续升级 Spine 导出版本，需要同步调整预览 runtime 版本。

当前预览页默认使用本地安装的官方 `@esotericsoftware/spine-player@4.1.56`。该版本 Player 使用 `jsonUrl` 和 `atlasUrl` 配置字段。若未来确认 `spine-webcomponents@4.1.*` 可用，也可以替换或并行支持 WebComponents。

## 资源要求

Spine 预览不能只靠 JSON，还需要 Spine 导出的 atlas 和贴图文件：

```text
example-json/
  skeleton-4.1.json
preview/
  xiaoren.atlas
  xiaoren.png
```

当前预览页默认使用 `example-json/skeleton-4.1.json` 作为 JSON，使用 `preview/xiaoren.atlas` 作为 atlas。Atlas 内引用的贴图路径是 `xiaoren.png`，因此 `preview/xiaoren.png` 必须和 atlas 放在同一目录。

除浏览器交互预览外，MCP 还提供离线诊断预览：`spine_create_preview_manifest` 固化输入 hash、runtime、采样和相机；`spine_render_animation_frames` 输出固定相机 PNG 帧；`spine_render_contact_sheet` 输出低 token 的联系图。该诊断层默认比较骨骼锚点和轨迹，不把不同角色的贴图像素差异当作质量结论。

## 启动方式

先构建项目：

```bash
npm run build
```

启动预览服务：

```bash
npm run preview
```

默认访问：

```text
http://127.0.0.1:5177
```

可用环境变量：

- `SPINE_MCP_WORKSPACE`：工作区根目录，默认当前目录。
- `SPINE_PREVIEW_PORT`：预览服务端口，默认 `5177`。
- `SPINE_PREVIEW_HOST`：监听地址，默认 `127.0.0.1`。

## 当前能力

- 静态提供 `preview/index.html`。
- 静态提供本地官方 runtime：`/vendor/spine-player/...`。
- 只允许浏览器读取工作区内文件。
- 通过 `/api/animations?file=...` 读取 JSON 动画和皮肤列表。
- 通过 `/api/hash?file=...` 读取 JSON hash。
- 通过 `/api/session` 读取 Agent 写入的当前预览会话状态。
- 通过 `/api/runtime-validate?file=...&atlas=...&animation=...` 使用官方 `spine-core` 读取 JSON、atlas 和附件数据。
- 预览页每 1.5 秒轮询 JSON hash，发现 MCP 写入后自动重新载入。
- 预览页每 1.2 秒轮询会话状态，发现 Agent 更新 JSON、atlas、动画或操作说明后自动同步界面。
- 页面支持填写 JSON 路径、atlas 路径、动画名、皮肤、播放速度、`premultipliedAlpha` 和 `mipmaps`。
- 页面会优先使用 JSON 中 `skeleton.x/y/width/height` 设置显式 viewport，避免 4.1 Player 自动计算动画 bounds 失败。
- 页面支持 URL 参数直达指定预览，例如 `?json=example-json/skeleton-4.1.json&atlas=preview/xiaoren.atlas&animation=walktest2&pma=true&mipmaps=false&autoload=true`。

## MCP 预览辅助工具

当前 MCP 提供以下预览、验证和观察辅助工具：

| 工具 | 用途 |
|---|---|
| `spine_preview_get_config` | 返回预览层默认 JSON、atlas、动画名、runtime 版本和 URL 参数说明。 |
| `spine_preview_check_assets` | 检查 JSON、atlas、atlas 引用贴图和目标动画是否齐全。 |
| `spine_preview_get_url` | 生成可直接打开的浏览器预览 URL，可指定动画、PMA、Mipmaps 和自动载入。 |
| `spine_runtime_validate` | 使用官方 `spine-core` 读取 JSON、atlas 和附件数据，确认资源能被当前 4.1 runtime 加载。 |
| `spine_run_validation_pipeline` | 执行写入后的推荐验证流水线，汇总结构校验、runtime 加载验证和预览 URL。 |
| `spine_preview_set_session` | 设置当前预览会话，供浏览器预览和未来 WinForms 自动观察。 |
| `spine_preview_get_session` | 读取当前预览会话和预览 URL。 |
| `spine_preview_clear_session` | 清空当前预览会话，恢复默认观察上下文。 |
| `spine_agent_ping` | Agent 身份与语义握手；在线绿灯另由实时 MCP 协议 ping 判定。 |
| `spine_agent_get_connection_status` | 读取 Agent 连接状态、项目检测结果和 Codex/Claude Code/opencode 配置片段。 |

这些工具只帮助 Agent 组织预览入口，不写入 JSON，也不绕过 MCP 的安全写入流程。

预览服务还提供 `GET /api/agent-connection?clientType=codex`，供 WinForms 读取同一连接状态。该接口只读，不写 Spine JSON，也不修改用户全局 Agent 配置。

## URL 参数

预览页支持以下 URL 参数：

- `json`：工作区内 Spine JSON 路径。
- `atlas`：工作区内 Spine atlas 路径。
- `animation`：要预览的动画名。
- `skin`：可选皮肤名。
- `speed`：播放速度，默认 `1`。
- `pma`：是否使用预乘 Alpha，例如 `true` 或 `false`。
- `mipmaps`：是否启用 Mipmaps，例如 `true` 或 `false`。
- `autoload`：页面打开后是否自动载入预览。

## 贴图边缘和切片显示问题

如果预览里出现切片边缘发黑、白边、半透明区域颜色异常，优先检查 `premultipliedAlpha` 是否和 Spine 导出 atlas 时的 Premultiply alpha 设置一致：

- 导出时开启 Premultiply alpha：预览页勾选“预乘 Alpha”。
- 导出时未开启 Premultiply alpha：预览页取消“预乘 Alpha”。

如果出现相邻切片串色、边缘采样到旁边区域，优先关闭 `Mipmaps`，并检查 Spine 打包 atlas 时是否有足够 padding / duplicate padding。当前预览页默认关闭 `Mipmaps`，减少调试阶段的采样串色。

## 和 MCP 的关系

推荐流程：

1. Agent 通过 MCP 对 JSON 执行 `dryRun`。
2. 用户确认 diff、官方规范审查和校验结果。
3. Agent 通过 MCP 真实写入，工具自动生成备份。
4. 浏览器预览页检测到 JSON hash 变化并自动重载。
5. 用户或 Agent 根据画面继续提出调整请求。

预览层不得绕过 MCP 修改 JSON。即使未来加入 WinForms，WinForms 也应调用 MCP 或本地桥接接口，而不是直接自由编辑 Spine JSON。

## Agent 驱动的会话状态

Agent 可通过 `spine_preview_set_session` 设置当前观察上下文：

- `filePath`：当前目标 JSON。
- `atlasPath`：当前 atlas。
- `animation`：当前动画。
- `skin`：当前皮肤。
- `speed`、`premultipliedAlpha`、`mipmaps`、`autoload`：预览参数。
- `operation`：当前操作说明，例如正在 dryRun、写入、验证或恢复。
- `log`：追加一条控制台日志。

浏览器预览页通过 `/api/session` 轮询该状态。未来 WinForms/WebView2 壳也应读取同一状态，而不是让用户在 WinForms 内手动决定操作目标。

## 实时预览验证流程

已验证的闭环流程：

1. 使用 `spine_preview_check_assets` 或 `/api/check-assets` 确认 JSON、atlas、png 和目标动画存在。
2. 使用 `spine_runtime_validate` 或 `/api/runtime-validate` 确认官方 4.1 runtime 能读取 JSON、atlas 和附件数据。
3. 使用 `spine_preview_get_url` 生成带参数预览链接，建议带上 `autoload=true`。
4. 打开预览页，确认状态显示“已载入 ... hash=...”，且页面中存在 canvas。
5. 使用 MCP 写工具先 `dryRun:true`，确认 `operationValidation.ok`、`officialSpecValidation.ok` 和 `validation.ok`。
6. 使用同一写工具传 `dryRun:false` 和最新 `expectedHash` 提交。
7. 再次调用 `spine_runtime_validate`，确认官方 runtime 仍能读取修改后的资源。
8. 预览页每 1.5 秒轮询 JSON hash，发现变化后自动重新载入同一动画。
9. 状态中的 hash 前缀应变为提交后的新 hash。

也可以在第 7 步直接调用 `spine_run_validation_pipeline`，它会一次性返回：

- `structureValidation`：等同 `spine_validate_json`。
- `runtimeValidation`：等同 `spine_runtime_validate`。
- `previewUrl`：等同 `spine_preview_get_url`。
- `recommendedNextSteps`：根据通过或失败给出下一步建议。

当前实际测试记录：

- 预览链接参数：`json=example-json/skeleton-4.1.json`、`atlas=preview/xiaoren.atlas`、`animation=preview-reload-test`、`pma=true`、`mipmaps=false`、`autoload=true`
- 写入前 hash 前缀：`433eb49e22c6`
- 写入后 hash 前缀：`0cc4d1776e39`
- 页面状态已自动更新为：`已载入 preview-reload-test。PMA=开，Mipmaps=关，hash=0cc4d1776e39。`

## 完整动画诊断实例（不批准、不提交）

`spine_retarget_motion` 新增 `diagnosticPreview:true`，仅支持 `dryRun`。用户要求观察整段失败候选时，可在保留未确认姿态和失败报告的前提下生成完整诊断动画：候选 JSON、实际关键时间关系比较、固定相机上下姿态图和目标原速 GIF。通过 `spine_render_animation_comparison` 生成上下同步 GIF。

诊断结果始终为 `ok:false`、`diagnosticOnly:true`、`readyToCommit:false`，分别返回 `numericOk`、`poseGate`、`keyGraphs` 和 `previewIssues`，不产生 `reviewToken`，不修改原角色。它是观察失败的独立出口，不能替代正式姿态/动画审查或用于提交。`diagnosticPreview:true,dryRun:false` 必须拒绝；渲染失败仍保留候选与错误。

实际验证脚本：`scripts/acceptance-animation-diagnostic.mjs`。先执行 `references`，Agent 查看参考连线图并填写逐阶段参考判断后执行 `animate`。脚本通过实际 MCP stdio 求解和渲染，仅创建工作流草稿，不自动批准任何目标姿态或完整动画。环境变量 `ANIMATION_DIAGNOSTIC_DIR` 可指定已有实例相对目录。

中文负例：把手目标设到骨骼不可达范围，再请求完整动画诊断。预期得到失败报告及 GIF、原 JSON 哈希未变、无提交令牌；请求真实写入仍应拒绝。不要把 GIF 生成成功描述为动画匹配通过。

## 解剖持杖手、身体视角及切片遮挡检查

参考 observation.actionSemantics 支持 `version:1 / weaponHand:left|right / identityStatus:confirmed / anatomicalBasis / bodyView / bodyViewBasis / occlusion`。身体视角可为 `frontThreeQuarter`、`side`、`backThreeQuarter`，参考有不确定性时可用 `sideOrBackThreeQuarter`。遮挡项保存 `{front,back,basis}`，语义部位可为 `body` 或已有肢体线段编号（如 `rightArm.1`）。缺少必要遮挡关系返回无法验证，不默认为通过。

`spine_calibrate_visual_rig` 增加 `anatomicalSides` 与 `viewProfiles`，均绑定确认指纹。解剖左右映射保持跨阶段稳定；视角配置保存实际附件状态、躯干插槽和看图校准依据。姿态 `frame.action.driver` 明确实际目标驱动手（如 `rightHand`），骨架比较独立输出 `action.weaponHand`、`action.bodyView`、`action.occlusion.*`。身体视角从 runtime 实际附件配置匹配已确认 profile；未经校准不能只传一个“背面”标签通过。遮挡用 runtime 绘制顺序回读。Agent 判断仍参与视角配置校准，这不是自动像素识别或数学上的视觉保证。

`frame.presentation` 支持受控 `attachments` 和完整 `drawOrder` 插槽排列，沿用 `spine_adjust_pose`、`spine_solve_pose` 和 v2 motion。显示状态在阶段边界离散切换，导出为已有 attachment/drawOrder 时间线；不改 setup、绑定、mesh、atlas 或 PNG。现有后发、面部显隐及背包层序可构造转身诊断候选，但不代表有完整三维转身模型。需要逐姿态查看轮廓并重新校准，不能自动批准隐藏五官后的身体视角。

中文验证：右手参考对应左手驱动必须失败；正面配置不能覆盖侧背参考；缺失视角/遮挡信息必须无法验证；同一附件状态不能标记成两种不同视角；遮挡层序反转必须失败。切片状态修改使配置匹配和旧审查失效。官方 runtime 回读 attachment/drawOrder 的阶段切换必须与单姿态一致。
