# 动画生成工作流

本项目现在分成三层：

1. `src/spineJson.ts`：受控 JSON 读取、写入、备份和规范审查。
2. `src/motionEngine.ts`、`src/motionMath.ts`：mapping 生命周期、IK、脚底锚点、动作 schema 和求解参数。
3. `src/mappingTools.ts`、`src/retargetEngine.ts`、`src/motionRuntime.ts`：校准报告、语义 motion 提取、runtime 几何和重定向门禁。
4. `src/server.ts`：把核心能力暴露成 MCP 工具。

## 最小流程

1. 调用 `spine_inspect_character` 读取角色骨骼和已有动画。
2. Agent 提供语义骨骼选择，调用 `spine_create_mapping_draft`。
3. 调用 `spine_validate_mapping` 和 `spine_calibrate_mapping`。
4. Agent 确认身体、左右侧、脚底/手腕锚点、弯曲方向和跟随骨骼，调用 `spine_confirm_mapping`。
5. 对参考动画调用 `spine_extract_motion`，生成角色无关的 v2 motion。
6. 调用 `spine_validate_motion` 检查 motion schema。
7. 调用 `spine_retarget_motion`，默认 `dryRun: true`。
8. 检查语义误差、IK 可达性、diff、规范审查和返回的 `reviewToken`。
9. 使用同一输入、`expectedHash` 和 `reviewToken`，再次以 `dryRun: false` 写入。
10. 调用 `spine_run_validation_pipeline` 和 `spine_validate_motion_result` 验证 runtime 与动作质量。

## 当前实现边界

Agent 的语义确认不再只靠提示词：mapping 必须经过 draft、validated、calibrated、confirmed 生命周期；校准报告记录角色 rig 指纹和 source hash，真实重定向写入前会强制检查确认状态和报告一致性。

当前 v2 求解器已包含两段式 IK、脚底锚点、单臂目标 IK、规则化跟随、绝对坐标三次曲线拟合和 runtime 网格顶点采样。不可达目标、脚底/手腕误差、首尾不闭合、旋转跳变或 runtime/schema 失败都会阻止真实写入。

底层 `spine_set_bone_keyframe` 等工具仍然保留，适合明确的局部微调。

## 示例和验证结果

`mappings/example-4.1.mapping.json` 已按 `example-json/skeleton-4.1.json` 的真实骨骼层级配置，并且校验器会检查每条手脚链是否连续。示例 walk 使用 9 个姿态点（包含首尾闭合姿态），不会按每一帧写入 JSON。

推荐的验证顺序是：

1. `spine_validate_mapping`
2. `spine_validate_motion`
3. `spine_retarget_motion`（先 `dryRun: true`）
4. `spine_retarget_motion`（确认 diff 后 `dryRun: false`）
5. `spine_fit_animation_curves`
6. `spine_run_validation_pipeline`

当前测试覆盖 mapping、动作格式、两段式 IK、脚底/手腕约束、重定向 dry-run、批处理失败隔离、JSON 规范、曲线拟合和官方 `spine-core` runtime 加载。离线预览层额外覆盖固定相机 manifest、PNG 贴图帧、contact sheet、缓存和 projectId 工作区登记。
