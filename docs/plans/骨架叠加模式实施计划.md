### 0.2 缺口的精确定位（根因，不是症状）

| # | 根因 | 症状 |
|---|---|---|
| R1 | 骨架层**只在姿态级**生效（`renderPoseComparison` / `refineReferencePose`），诊断图为上下排列 | 骨架看不见"叠在一起"的偏差 |
| R2 | `animationReview.ts` 的 `renderAnimationComparison` **完全没引用骨架层**，只 `drawImage` 整幅外观 | npc1 叠图看到"两个不同角色" |
| R3 | 骨架残差的「改 → 看偏差 → 再改」闭环在**姿态生成阶段结束**，动画回放时不再迭代 | 叠图是审查产物，不是调整工具 |

**因此不需要新建 pose estimation + retarget 链路**（上一轮该建议作废）。能力大部分已造好，只是没贯通到动画级叠图。

### 0.3 决定性约束：参考侧是单帧标注，目标侧是逐帧

实测 npc1 真实数据：

| 侧 | 数据 | 形态 |
|---|---|---|
| 参考 | `pose-comparison.json` 的 `reference.time = 0`、`imagePath = frame-0000.png` | **单帧**静态标注（14 个关节点 + edges） |
| 参考 | `reference-manifest.json` | 34 帧像素图，**无逐帧关节点** |
| 目标 | `preview-manifest.json` 的 `trajectories` | **108 帧**，每帧 `bones` 含 53 根骨骼 `worldX/worldY`；`semantic` **全部为空**（0/108，因该次渲染未传 `mappingPath`，见 `previewRenderTools.ts:79-85`） |

**推论（必须写进方案边界）**：本计划能做的是「**已标注的参考关键姿态骨架** vs **目标动画逐帧骨架**」的叠加，等价于 3D MCP 官方推荐的 `render_video_overlay` **for exact key poses**，**不是逐帧骨架追踪**。要逐帧追踪参考骨架，必须先有参考侧逐帧关节点标注（当前项目无此能力，属另一条链路，不在本计划范围）。

### 0.4 坐标系映射（实施时最需小心处）

`animationReview.ts:17` 现有叠加用一套参数，`poseWorkflow.ts:216-224` 姿态诊断页用**另一套**：

| 侧 | 现有函数 | 投影 |
|---|---|---|
| 参考帧（动画级） | `animationReview.ts` | `rs = poses.targetScale*poses.standardHeight/view.height`；`refY = h*.9-(groundY-crop[1])*rs`；`refX = w/2-crop[2]*rs/2` |
| 参考点（姿态级） | `poseWorkflow.ts:224` | `rs = height*.7/r.height`；`[x+dx+(px-rx)*rs, dy+(py-ry)*rs]` |
| 目标点（姿态级） | `poseWorkflow.ts:219` | `project(x,y) = [(x-bounds.minX)*sc, (bounds.maxY-y)*sc]`，`sc = height*.7/standardHeight` |

两处 `rs` 定义不同。**动画级叠加骨架时，参考关节点必须复用 `animationReview.ts` 的 `rs/refX/refY`**，目标关节点必须投到同一 `target.canvas`，否则会产生假性错位。现有 `hashObject(poses.bounds)===hashObject(target.bounds)` 校验（`:16`）保证 bounds 一致，是复用前提。

## 1. 目标与范围

**目标**：`spine_render_animation_comparison` 增加 `layout:'skeleton'`，在同一画布上叠加：
- 参考侧：已标注关节点 + 连线（复用 `drawReferenceSkeleton`）
- 目标侧：逐帧骨架（从既有数据取，不重跑 runtime）
- 附：`compareGraphs` 的 metrics 摘要作为数值证据

**范围**：只读渲染与证据输出。不新增、删除、重命名任何 MCP 工具（保持 116），不触碰 V1 写入边界，不重跑 runtime 求解，不引入姿态估计模型。

## 2. 实施项

### ① `layout:'skeleton'` 叠加布局

**落点**：`src/animationReview.ts`、`src/animationCommands.ts`、`src/server.ts`

**Step 1 — 参数登记（三处，缺一不暴露）**
1. `animationCommands.ts` 的 `poseOperationArguments['spine_render_animation_comparison']` 增加 `skeleton`（及 ② 的 `metrics`）。
2. `server.ts` 的 `poseProperties` 增加 `skeleton`（boolean，默认 false）与 `metrics`（boolean，默认 true）定义。
3. `server.ts` 的 `poseToolDefinitions` 中该工具描述补充 skeleton 模式说明。

**Step 2 — 数据准备（只读，不重跑 runtime）**
- 参考侧：`poses.reference`（14 点 + edges + crop/height/groundY/facing）已从 `poseManifestPath` 读入，直接可用。
- 目标侧：从 `target.trajectories[i].bones`（逐帧 53 根骨骼世界坐标）取点。**需解决"骨骼名 → 语义 role"映射**：
  - 首选：复用 `visualRig.ts` 的 `readVisualNodes` 语义，但该函数输入是 `skeleton` 实例，本工具没有 → 改为读 `visualRigPath` 配置文件中的 `nodes[role]`（`boneLocal`/`meshTriangle`）做静态映射，把 `bones[node.bone].x/y` 取出作为该 role 的坐标。
  - 需新增可选入参 `visualRigPath`（filePathProperty）；缺省时**降级**为按 `target.trajectories[i].bones` 的 key 顺序画骨骼连线（明确标注"未校准语义映射，仅供轨迹观察"），不得静默当作已校准骨架。
- 骨架连线：参考侧用 `poses.reference.edges`；目标侧优先用 `visualRig` 的 `segments`/`edges`，缺省时按角色 JSON 的 `bones[].parent` 连父子线（需从 `target.filePath` 读，实施前确认该文件在 workspace 内）。

**Step 3 — 统一投影**
- 参考点：复用 `animationReview.ts` 既有 `rs/refX/refY`，`project(px,py) = [refX+(px-crop[0])*rs, refY+(py-crop[1])*rs]`。
- 目标点：`project(x,y) = [(x-bounds.minX)*sc, (bounds.maxY-y)*sc]`，`sc` 由 `target.canvas` 与 `target.bounds` 推出（`w/(bounds.maxX-bounds.minX)`），与 `poseWorkflow.ts` 口径一致。
- **关键**：两投影结果必须落在同一 `w×h` 画布；实施后必须用数值断言验证（见 §4）。

**Step 4 — 绘制**
- 画布：`createCanvas(w, h+44)`（复用 ② 已实现的两行标签区）。
- 参考骨架：`drawReferenceSkeleton(ctx, poses.reference, projectRef)`，用半透明或描边色区分。
- 目标骨架：逐帧从 `trajectories[i]` 取点，用 `drawVisualGraph` 或等价绘制（若缺 `comparison` 则传 `undefined`，函数已兼容）；颜色与参考侧区分（建议左绿右橙沿用既有图例）。
- 标签：`skeleton ref <rt>s / tgt <t>s`，并在报告中输出 `skeletonSource: 'reference-single-frame'`、`targetSource: 'trajectories.bones'`、`semanticMapped: boolean`。

**Step 5 — 布局枚举与门禁**
- `layout` 枚举从 `['reference-above-target','overlay']` 扩为 `['reference-above-target','overlay','skeleton']`。
- `reviewAnimation` 的布局门禁（`:46`）同步接受 `'skeleton'`；**证据绑定强制校验保持不放宽**。
- 默认布局不变，既有证据与字节级回归不受影响。

### ② metrics 数值证据输出

**落点**：`src/animationReview.ts`

- 新增 `metrics`（boolean，默认 true）：`skeleton` 布局下输出 `compareGraphs` 的结构指标摘要（每个 metric 的 `id/status/error/tolerance`），**只输出，不自动判定通过/失败、不批准**。
- 前置：`compareGraphs` 需要 `correspondence`（在 pose 文件中，`pose-comparison.json` 的 `poses[]` **不含**该字段）与归一化后的两侧 points。若取不到 `correspondence` 或语义映射缺失，输出 `metrics: null` + `metricsReason`，**不得编造**。
- 与既有 `refineReferencePose` 的 `graphResiduals` 体系保持口径一致（同一 `compareGraphs`），不另造一套指标。
- 报告字段：`skeletonMetrics`（摘要）、`metricsUnavailableReason`。

### ③ 单帧快速迭代（闭环前半，本计划**只登记、不实施**）

- 复用已实现的 `times` 参数：`layout:'skeleton' + times:[t]` 即可只出指定帧，配合 `outputDir` 覆盖，形成"调一次看一帧"的最小闭环。
- **真正的闭环**（改 pose → 即时重出叠图 → 看偏差 → 再改）需要把叠图前移到制作阶段，涉及 `renderAnimationFrames` 重跑与会话状态，**单独评估，不在本计划实施**。

## 3. 顺序与依赖

```
① 参数登记 + 数据准备 + 投影 + 绘制 + 门禁   （主体）
        ↓
② metrics 输出                              （依赖 ① 的语义映射）
        ↓
③ 闭环                                      （仅登记，另议）
```

① 内建议顺序：先 Step 1（可独立验证 schema）→ Step 3（投影数值断言）→ Step 2（数据）→ Step 4（绘制）→ Step 5（门禁）。**投影先行**可最早暴露"两套 rs 不一致"这一最大风险。

## 4. 验证方式

| 层级 | 做法 |
|---|---|
| 编译 | `npm run build` |
| 单测 | 分文件跑（**不以全量 `npm test` 为准**：宿主 `safe-delete` 批量守卫稳定失败 25 项，与改动无关）。新增 `test/skeletonOverlay.test.ts` |
| **数值断言（关键）** | 构造已知点，断言 `projectRef(参考点)` 与 `projectTarget(目标点)` 落在同一 `w×h` 画布且比例一致；断言两套 `rs` 复用后无假性错位 |
| 回归 | `reference-above-target` 与 `overlay` 两种既有布局的产物必须与实施前**字节相同**（已有 npc1 基线：2561368 bytes / 108 帧） |
| **真实资产验证** | 复用 `test-output/npc1-verify/` 隔离副本（147 文件）。需补复制：`目标/npc1.json`（角色骨骼父子）、`trial/npc1.visual-rig.json`（语义映射，旧项目存在，见 `/d/AI_cc/spine test/body-reference-trials/.../trial/npc1.visual-rig.json`） |
| 端到端 | MCP stdio 调用 `layout:'skeleton'`，确认 `content` 含 `image`、`isError:false`、报告含 `skeletonMetrics`/`skeletonSource` |
| 视觉 | 出图确认两侧骨架**在同一坐标系**（不是两套错位骨架）；确认参考骨架标注为单帧、未伪装成逐帧 |

**诚实边界**：参考侧骨架是 `time=0` 单帧标注，因此 skeleton 图**只能证明"目标该帧 vs 参考关键姿态"的关节偏差**，不能证明逐帧对齐。报告中必须显式标注，避免后续链路误用。

## 5. 不做的事（范围约束）

- 不新增、删除、重命名任何 MCP 工具（保持 116）。
- 不重跑 runtime 求解、不引入姿态估计模型、不生成参考侧逐帧关节点。
- 不自动判定 `compareGraphs` 通过/失败、不批准、不改 pose、不写 Spine JSON。
- 不实现「改 pose → 即时重出叠图」闭环（③ 仅登记）。
- 不改 `reference-above-target` 与 `overlay` 的既有行为与产物。
- 不动 V1 写入边界；全部为只读渲染与证据输出。

## 6. 风险与待确认项

| # | 风险 / 待确认 | 处理 |
