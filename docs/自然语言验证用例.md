# 自然语言验证用例

## 普通创作验收

- 给 Agent 动态参考和目标角色，允许直接开草稿。先交付可预览的动作，再按自然语言反馈调整指定时间区间并核对撤销和重做。
- 给 Agent 已有 .spine 动画作为参考，按需查轨道、时间和画面。追加真实参与播放的骨骼、插槽及切片，另存原生工程并用实际编辑器回读。
- “按换装立绘重新拆衣物，沿用原动画，并在观察器看操作”：用新轮廓 PNG 和网格替换独立草稿的目标附件。核对切片边缘、全部原动画的引用、抬手时的袖口及裙摆。通过同工作区的 MCP 预览会话发布实际进度和 runtime 预览，随后复开另存的工程。
- “复刻这段 Spine 动画”：提示词省略 MCP 和观察器，仍使用同工作区 MCP。核验开草稿、实际编辑、当前修订 GIF 和实际发布自动同步到观察器，无需额外调用设置会话。编辑预演、发布预演及历史修订回看后会话保持原修订。
- 分别记录提示词、真实工具轨迹、构建指纹、MCP/Host 会话、源和交付哈希。普通创作的 formalEligible 记录为不适用。


“还没批准怎么先看连续效果”：校准创建即生成诊断扫掠 GIF/联系图，逐帧回读且不生成正式 motion。若切片连接失败或连续性数值失败，保留诊断并退回，不自动缩窄范围或批准。回放补偿必须在角色校准范围，禁止手填 scaleLimits 或任意放大其它骨骼。

“keypose 和 mapping 还是不对”：统一入口先做输入视觉审查。参考 pose 的可见点若落在背景上，或 npc1 visualRig 的四肢节点仍全是骨骼原点、髋膝低置信度、face 没有前脸依据，任务停止在 binding；此时先重出参考放大联系表和 visualRig 校准图，不能继续调 IK 或把诊断 GIF 当成动作结果。

补充规则：输入审查还必须确认每个 keypose 的解剖左右、支撑脚、朝向和前后证据；mapping 与 visualRig 的三段骨骼链、切片 attachment 和指纹也必须一致。若出现 `KEYPOSE_IDENTITY_UNCONFIRMED`、`KEYPOSE_SUPPORT_UNCONFIRMED` 或 `MAPPING_ANATOMICAL_SIDE_MISMATCH`，应先修复标注或绑定，再重新执行。`MAPPING_SEGMENT_ATTACHMENT_REUSED` 只在跨骨骼加权网格需要人工复核时作为 warning，不得把合法加权切片误判为硬错误。`adaptive` 只适配已确认的动作语义，不能把错误输入当作几何残差放过。
## 2026-10-26 区间与世界投影校准用例

- “只改 0–1 秒中间抬头”：边界必须存在；内部 .5 秒可插入 head 参数，边界及其它区间的采样相同。正式关键姿态只允许替换已批准 posePath。
- “把下一阶段挪过来”“顺便换支撑/分支/层序”：拒绝跨区间、重复时间、阶段重排和固定字段变更；整批不半应用。
- “撤销、重启继续、另存再打开”：产生新版本，重新求解出图，重新核验依赖及 pin；旧截图、旧视觉批准不恢复。
- “这条手臂缩短到原投影的 0.7”：使用 upper/lower 世界段长比，求解并报告实际比例及局部 scale；两者不能等同。缺独立校准/批准、过期哈希、超范围、分支不符或约束接管均拒绝。
- “宽一点”“试验图看起来可以直接正式用”：未校准宽度保持 1；旧诊断批准不迁移。所有样本须真实 player 图、实际 runtime 和五项不同具体理由。
- “播放、暂停并拖到关键姿态”：仅本地呈现当前候选；不会把播放时间当作文档修改或批准。正式证据由 MCP 暂停并核验。

机械回归、npc1 数值试用、独立 Agent 看图和编辑器导入分别报告；自动页面权限审核超时不计作视觉通过。后续真实页面已验播放/暂停/定位：0.55–1 宽范围数值通过但独立看图退回；另建的 0.85–1 固定范围经新证据独立批准，受限试用 motion 官方导入保存通过，不批准原 GIF。两条记录分别保留，不能从宽范围失败中继承批准。

2026-10-26 独立新阶段：

- “新参考不匹配，但让我继续改”：显式 newStage，默认预演；实际操作载入独立内存草稿，旧姿态绑定不变，拟保存路径没有新资产文件。先重新 pin，再改、看图、撤销。
- “有必要节点看不清”：返回 partialResult 和已有比较/缺项，拒绝载入完整阶段；不编造参考点。
- “重启后接着改”：从任务 diagnosticContexts 找 ID；隔离 Host 显式 --resume 后，先预演来源/差异，再恢复。新 openEpoch 不认旧版本和旧截图，旧批准不恢复。
- “把失败结果先保存”：正式提交拒绝；只有当前门禁通过才能备份另存新受管姿态。完整动画资格另验。
- “保存后响应丢了”：按 journal 和目标精确哈希裁决；同一 requestId 取原回执，不重复写文件，未知字节保持冻结。

合成可达/不可达夹具只检验门禁与故障恢复；真实 npc1 检验载入/修改/看图/恢复，仍有必要参考失败，不能称动作完成。

2026-10-26 参考准备补齐：

- “先用这个 GIF 开始，不要生成姿态”：省略 stages 建立 referencePreparation，下一步正式拆帧，原时序不变；不得伪造姿态、启动 Host 或取得 Writer。
- “把这些已审查参考组成动作记录”：`spine_create_pose_sequence` 自动绑定参考/rig 指纹，但仍要求明确左右身份和依据、weaponHand 及唯一 stageId；未知必要点、未审查/过期证据或视角不支持均拒绝。
- “把新记录用于试用”：通过 isolatedDirectory 在全新受管副本登记，原清单不变；不把旧阶段静默切换到新参考，也不继承动作批准。
- “继续我保存的这一版”：读取 stageContexts，以 documentPath 显式选择已提交后续修订；跨来源族、改固定绑定或哈希不符拒绝，任务提示保持当前阶段。
- “这个工具没显示出来”：动态目录只引导查询对应组，不返回不可调用的修改建议或自动扩大权限。

2026-10-26 追加真实 npc1 检查：固定臂长下参考肘角与肩腕距离区间冲突须明确报告，不自动改身份、支撑、弯曲分支或阈值；缺少标尺或透视未知返回 unknown。真实 MCP 取消后核对服务端版本与输出，不能只凭客户端取消成功；恢复先列 journal 来源/差异，显式继续后不继承批准；提交重试复用 requestId 返回原回执，不同内容同 ID 拒绝。证据见 [恢复验证](plans/creation-recovery-2026-10-26T04-19-15-938Z.json)。

## 部件观测与受控单臂缩短（2026-10-25）

- “这条小臂的角度能确定吗”：优先核对显式像素误差圆与刚性身体轮廓。遮挡、缺半径、近圆或衣袖时使用两个既有节点连线给出近似数值，标 `twoPoint/estimated`，不因缺轮廓卡住；缺误差不从 confidence 编造，未知半径保持 null。可靠证据冲突或两个节点未知/重合时说明缺项，保留可用诊断。原 15° 等动作门禁继续执行。
- “先把单臂向镜头收拢试试看”：建立明确创作依据的 diagnostic perspective，只在隔离 C2/新诊断修订中改变单臂倍率；实际 runtime 回读端点、方向、分支及切片。缩短不自动证明朝向镜头，前后关系仍需依据。
- “绿色数值通过，直接生成整段动画”：拒绝透视诊断的正式批准、motion 组装及源动画提交；先校准角色范围和连续动作。参考必要节点未知时不继续修正或批准整段。
- “强缩短后目标到不了”：保留失败诊断，不移动支撑/躯干或交换身份来宣布成功。真实 npc1 温和 0.9/0.85 通过，0.8/0.7 失败均保留。[试验](身体部件观测与透视缩放-20261025.md)。

## state/回放性能优化的安全回归（2026-10-24）

- “连续查询当前状态”：每次重新核对真实根/文件字节，不能因同 size/mtime 或上一请求结果而跳过；只在同次只读请求按真实身份去重。
- “查询过程中切换工程文档”：旧依赖核验不能宣称新文档已核验，返回 TARGET_DRIFT 状态，重新查询后恢复。
- “链接目标或工作区根中途改指”：目标逐项核验，根在当前请求固定；改指越界、断链/缺失拒绝，新请求重新核对根。
- “读取另一尺寸或已缓存帧”：计算缓存仍绑定完整候选/选择及依赖；篡改 live 或选择后不得返回旧 PNG，也不继承视觉批准。
- “端口/control 已更新”：本次并发读盘后核对实际实例，错配拒绝，不能使用上一轮凭据。

## C2-4c 精确动画及源事务（2026-10-24）

- “将当前 motion 制作成角色动画”：显式选同名动画/时间，完整版本制作精确候选和完整报告；不直接写源，准备令牌不作批准。
- “看完整动作再批准”：检查原速 GIF、全部关键姿态、适用上下参考对比和当前 player；五项独立具体理由，任何必要关系失败或证据陈旧都不得批准。
- “保存已批准动画”：显式 animation pin，指定精确 animationCandidateHash/expectedHash/reviewToken/源路径及 requestId；默认预演，真实提交备份后仅替换一个动画。
- “提交后继续做下一版”：新 revision 清除旧结果，显式覆盖、重算/重新截图及批准；mapping/报告原字节不改，只认可可核验的已提交动画来源链。
- “源文件被别人修改/备份失败/回执丢失”：分别拒绝漂移、保留目标或冻结恢复；相同 requestId 返回原回执，不能自动重放未知事务。
- 合成模拟页面只验证协议；真实 WebView2 合成 29 项只验证实际渲染链路，均不能代替第二真实角色或独立编辑器导入。

## C2-4b 新资产闭环（2026-10-24）

- “从角色建立首个站姿”：隔离 C2 打开受管 skeleton，查询 assetDrafts，用完整版本及 pin intent:asset 绑定来源；create 默认预演，false 暂存，独立 asset commit，源骨架字节不变。
- “生成姿态/适配参考后保存”：false 只返回暂存哈希，须精确 assetCandidateHash/outputPath 和稳定 requestId；switched:false 后显式打开新资产，再重算及独立视觉审查。
- “从未保存姿态拼 motion”：拒绝把内存改动登记为旧磁盘依赖；先保存及批准，motion 必须登记同角色标准和阶段来源。
- “继续修正参考姿态”：只用当前内存和静态派生比较，最多 60 次，旧 comparisonPath/reportPath 拒绝；失败仅诊断，无保存授权，成功不继承批准。
- “保存响应丢失/中断”：稳定 requestId 返回原回执；发布后未知冻结，取得排他权并打开来源，按日志和实际字节裁决，不重复创建或丢失来源未提交编辑。

## C2-4b 内存资产计算基础（2026-10-23）

- “从当前标准站姿创建关键姿态”：内部计算传入明确姿态值，重新验证数值/参考/证据，只返回 draft，不能继承批准。当前高级工具 attached 保存尚未开放，不能回退磁盘创建。
- “磁盘旧版已经批准，当前内存改坏也继续”：拒绝当前失效输入；有效旧磁盘不能替代本次内存值。
- “从几个已确认姿态生成 motion”：标准类型、同角色/地面、action 标准绑定、阶段唯一且递增并覆盖起止均须通过；参考阶段还需一致身份/绑定及独立具体理由。
- “motion 改了地面或重复阶段，直接预览”：poseWorkflow 复核与生成共用门禁，失败阻止发布。预览可信度不代替动作批准。
- “计算时给 dryRun:false 顺便保存”：内部 Data 入口仍只计算；资产保存必须接入独立受控事务。目前跨类型登记、Host 原子保存及高级工具 attached 调用未完成，不报告整项交付。

## C2-4a 附着姿态命令（2026-10-23）

- “用原来的通道/手脚工具调整当前草稿”：确认 C2 commandAdapters 和 patch readiness，给完整版本及当前 posePath，不给 outputPosePath；默认预演，真实执行保留内存中其它未保存改动并返回当前 PNG。
- “身体/头/通道和附件层序一起改”：adjust 的 patch.frame 转为同一批原子操作；batch 只接 target/channel。一个 revision、一次 undo，缺失绑定、重复路径或后项失败不半应用。
- “沿用旧 outputPosePath 顺便保存”：附着命令拒绝，不悄悄忽略路径；独立用 spine_host_commit 预演和保存新修订。detached 则必须新路径，不接受 Host expectedRevision。
- “拿刚才版本改另一份同名姿态”：完整身份或路径不符拒绝，不重读旧磁盘或猜新版本。C1/mirror、未适配参考/资产创建工具不扩权。
- “批次里顺便解除接地、改 weapon 或参考”：整批拒绝；render:true/region 也不替代当前 player 证据，render:false 保持无旧对比图。
- “连接时取消”：发送修改前停止；若修改已确认、重算期间取消，则保留真实新版本与未提交 journal，重开恢复，不宣称回滚。
- “motion 有 poseWorkflow 就算已批准”：检查原 poseGate.ok；未通过标准/关键姿态审查则拒绝发布，不因 await 返回或图像能加载默认通过。

真实 WebView2 合成组合姿态的数值失败继续显示“未通过”；player 核验和重连像素一致也不提升为美术批准。参考创建/适配、motion 资产与动画提交仍按后续子项验收。

## 长期观察与启停回归（2026-10-23）

同日 C2 首批隔离用例：

- “身体转两度、头转五度，调整躯干通道和脚横坐标”：先查询 capabilities.editing，只有 c2-pose 才发一个多项 dryRun；确认后整批真实编辑、一个 revision，经 MCP 回读实际 runtime 与 PNG。通道和 body 同骨骼时说明增量累加。
- “批次后半项失败也保留前半项”：整批拒绝，内存、栈、revision、journal 和源文件不变；重复路径、非有限数、未知字段同样拒绝。
- “顺便改支撑脚、弯曲侧、地面或参考”：不属于本批普通补丁；保持固定条件，不以姿态参数入口绕过各自审查。接地脚 y 或持杖手 x/y 受控时明确拒绝。
- “撤销刚才五项修改”：一次 undo 恢复整批输入，但 revision 增加，不恢复旧批准；重做同理。重启后的 C2 journal 重验参数和绑定，C1 实例拒绝重放扩展内容。
- “C1 已有批准，直接开 C2”：拒绝范围不匹配。HTTP 不接收 profile 切换字段，生产命令行没有 C2 入口，工具 schema 可发现不等于当前实例有权限。

## 失败用例

v2 语义流程新增验收用例：

- “这个角色是第一次用，先生成 mapping 草稿”：应调用 `spine_create_mapping_draft`，不得直接真实生成动画。
- “确认角色的左右手脚和脚底点”：应先校准，再调用 `spine_confirm_mapping`，保存确认者和完整 semanticChecks。
- “把参考 walk 提取成可复用动作”：应调用 `spine_extract_motion`，输出 v2 motion 和提取报告。
- “提交刚才通过的动作”：必须传入 dryRun 返回的 `reviewToken` 和 `expectedHash`。
- “使用 draft mapping 直接写动画”：应拒绝。
- “角色已经变化，但继续用旧校准报告”：应拒绝并要求重新校准。
- “目标不可达或脚底误差超阈值仍然写入”：应返回失败报告且不写文件。

## 跨角色 adaptive 重定向用例

- 新调用省略 `retargetMode` 时按 `adaptive` 处理；同角色精确复现可显式使用 `strict`。
- “目标角色手臂较短但仍能握住武器”：优先保持握持、攻击方向、支撑脚和弯曲侧；腕到躯干距离等几何差异写入 `relaxedConstraints` 与 `residuals`，状态为 `geometric-adapted`，不因单项腕位失败拒绝 expected target。
- “目标角色髋宽、腿长不同”：按目标角色 neutral pose、髋宽和自身链长重新生成站距与支撑中心；不复制参考左右脚绝对高度或绝对间距。
- “参考双脚高度冲突”：adaptive 以目标地面、脚底锚点和支撑身份为准；目标自身不可达时才返回 `unresolved`。
- “参考和目标 neutral pose 不同”：迁移相对关节角和弯曲方向，不能把参考角色绝对关节位置直接写给目标角色。
- `semantic-pass` 与 `geometric-adapted` 仍必须有 runtime actual、逐帧 `visualPoints`、采样指纹、同步对比和人工视觉证据；握持断裂、接地失败、不可达或语义硬约束失败仍阻断正式验收。

### `body.gif → npc1` 诊断验证

诊断验证必须使用同一份 `body.gif`、`body.sequence.json`、`ready-v1.reference.json`、`neutral-stand-v2.pose.json`、`npc1.visual-rig.json` 和 `目标/npc1.json`。`diagnosticPreview:true` 只读保留失败候选，不产生提交令牌；输入 GIF、sequence、参考姿态、visualRig、mapping 或角色结构指纹不一致时，在渲染前报告 `REFERENCE_BINDING_MISMATCH`。当前 sequence 只覆盖 `ready`，报告必须显示 `coverageStages:["ready"]` 和未审查帧数量，输出 GIF 不能代表完整动作验收。诊断 manifest 还必须分别报告 `semanticFailures`、`reachabilityFailures`、`structuralResiduals` 和 `styleResiduals`；比较 GIF 顶部显示 `DIAGNOSTIC ONLY`、`READY ONLY`、`UNRESOLVED` 或当前状态，画面不堆叠逐项失败文字。

- 旧 pose、motion、manifest 缺少 `retargetMode` 时按 `strict` 复核，避免历史批准结果改变含义。

## 解剖持杖手、身体视角及切片遮挡检查

参考 observation.actionSemantics 支持 `version:1 / weaponHand:left|right / identityStatus:confirmed / anatomicalBasis / bodyView / bodyViewBasis / occlusion`。身体视角可为 `frontThreeQuarter`、`side`、`backThreeQuarter`，参考有不确定性时可用 `sideOrBackThreeQuarter`。遮挡项保存 `{front,back,basis}`，语义部位可为 `body` 或已有肢体线段编号（如 `rightArm.1`）。缺少必要遮挡关系返回无法验证，不默认为通过。

`spine_calibrate_visual_rig` 增加 `anatomicalSides` 与 `viewProfiles`，均绑定确认指纹。解剖左右映射保持跨阶段稳定；视角配置保存实际附件状态、躯干插槽和看图校准依据。姿态 `frame.action.driver` 明确实际目标驱动手（如 `rightHand`），骨架比较独立输出 `action.weaponHand`、`action.bodyView`、`action.occlusion.*`。身体视角从 runtime 实际附件配置匹配已确认 profile；未经校准不能只传一个“背面”标签通过。遮挡用 runtime 绘制顺序回读。Agent 判断仍参与视角配置校准，这不是自动像素识别或数学上的视觉保证。

`frame.presentation` 支持受控 `attachments` 和完整 `drawOrder` 插槽排列，沿用 `spine_adjust_pose`、`spine_solve_pose` 和 v2 motion。显示状态在阶段边界离散切换，导出为已有 attachment/drawOrder 时间线；不改 setup、绑定、mesh、atlas 或 PNG。现有后发、面部显隐及背包层序可构造转身诊断候选，但不代表有完整三维转身模型。需要逐姿态查看轮廓并重新校准，不能自动批准隐藏五官后的身体视角。

中文验证：右手参考对应左手驱动必须失败；正面配置不能覆盖侧背参考；缺失视角/遮挡信息必须无法验证；同一附件状态不能标记成两种不同视角；遮挡层序反转必须失败。切片状态修改使配置匹配和旧审查失效。官方 runtime 回读 attachment/drawOrder 的阶段切换必须与单姿态一致。

## 统一任务入口验证

常见任务优先调用 `spine_execute_task`。验证时必须检查返回的 `workflowProfile`、`retargetMode`、`stopLayer`、`completedSteps`、`blockingReasons`、`nextAction` 和 `artifacts`，不能只看 `ok`。

修改后的案例还必须按真实链路验证：重新 `npm run build`，重启 MCP/Host，用自然语言提示词触发 `spine_execute_task`，确认 runtime 回读，并通过 MCP 预览生成目标 GIF 与同步对比 GIF。`adaptive-preview` 看到的是连续诊断候选，不代表正式通过；报告中的 `buildIdentity.stale` 必须为 `false`，且必须保留 prompt、tool trace、Host 会话和产物哈希。

- “检查 npc1 角色结构”应进入 `creative`，返回骨骼、动画和 mapping 候选。
- “把 body.gif 适配到 npc1”默认进入 `adaptive-preview`；若 sequence 只覆盖 `ready`，返回 `stopLayer:"coverage"`、诊断 GIF 和未审查帧数量，不宣称完整动作完成。
- “准备正式候选并审查”才允许显式进入 `production`；覆盖不完整时必须保留 `REFERENCE_COVERAGE_INCOMPLETE`。
- 视觉任务默认检查目标 GIF、参考/目标比较 GIF、动态比较 GIF 和 manifest；渲染失败时停止在 `evidence`，不得返回视觉完成。
- `readyToCommit:true` 只表示证据和审查条件齐备，真实写入仍需显式 Host 提交。
