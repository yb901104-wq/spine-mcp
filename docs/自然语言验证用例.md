# 自然语言验证用例

## 参考先行与姿态审查

- “先给参考攻击的六个阶段画关节连线。”应先产生参考原图/标注图，显示可见实线、遮挡虚线和不确定性，再审查参考。
- “参考肘部看不到，不要猜。”应记录 unknown，无坐标，不连接该点。
- “直接批准这张旧目标对比。”若 inline reference 未独立审查，应拒绝；旧文件仍可诊断。
- “正常站立不要蹲着。”默认膝屈曲不超过30°，失败需修改目标，不能自行放宽。
- “把反挥的手向后移，再看局部。”应创建新姿态修订、重算 IK 和指定阶段放大图，原批准失效。
- “不预览，直接批量提交。”缺少姿态或完整动画审查应失败；其他独立任务继续报告。
- “参考图和目标怎么都数值通过却不像？”应比较动作轮廓与方向，退回关键姿态，不能以可达性代替视觉审查。

测试覆盖参考标注字段、实/虚线及 unknown、证据篡改、参考审查缺失和修改失效、双角色姿态工作流、分页及显式结束帧。npc1 攻击已作为无武器比例适配通过 Agent 审查和 MCP 安全提交，编辑器导入未验证；见 [npc1姿态实例复验](npc1姿态实例复验.md)。新增快速稀疏姿态补间与0.90s参考浮点边界测试。

## 预乘 Alpha 预览回归

输入：“勾选了预乘仍有白亮和彩色块”：检查 atlas pma 标记及纹理格式，而非只检查 checkbox。用 NPC1 直通贴图验证：勾选 PMA，页面显示已转换预览纹理，角色无透明区域彩色块；已为 PMA 的 atlas 不重复预乘；取消选项重新载入；原 PNG/atlas 字节不变。

## Agent 接入验收

“帮我配置当前项目的 Agent”：观察平台选客户端、点击一键配置、核对路径后写入，保留其他 MCP 并备份。已配置但未加载不显示绿灯。客户端加载后，协议 ping 自动检测空闲连接，关闭客户端后转红；只有历史 spine_agent_ping 不应变绿。两客户端并行时一个退出不影响另一个。过期配置 hash、跨源安装请求、JSONC 冲突必须拒绝。说明见 [Agent一键配置与实时连接](Agent一键配置与实时连接.md)。

## 实际角色细节调整回归

输入：“保留原动作，把左手在指定主要姿态往右移动一点；然后缩小或增大步幅，并提供对比。”应保存独立 v2 motion，调用对应手目标/步幅工具，再重定向 dryRun 并审查误差，通过后提交测试副本。不能把保存 motion 的成功当作动画验收。输入不可达手目标必须拒绝提交；最后一帧 curve 与过期 expectedHash 必须拒绝。可重复脚本和 idle 误差改善见 [细节工具实测验收](细节工具实测验收.md)。

本文档用于验证 Agent 是否能根据自然语言正确选择和组合 Spine MCP 工具。所有写入类用例默认先要求 `dryRun: true`。

## 使用前准备

- 推荐测试文件：`example-json/skeleton-4.1.json`
- 推荐先对样本复制一份再做真实写入。
- 每个写入类用例建议先让 Agent 调用 `spine_get_document_summary` 获取当前 `hash`，再把它作为 `expectedHash` 传给写工具。
- 如果要验证完整链路，优先使用 `docs/标准演示用例.md` 中的 `demo-walk-loop` 剧本。

## 读取类用例

| 自然语言说法 | 期望工具 | 验收点 |
|---|---|---|
| 查看这个 JSON 的文档摘要。 | `spine_get_document_summary` | 返回版本、hash、骨骼/插槽/皮肤/动画数量。 |
| 查看当前 MCP 按哪些 Spine 官方 JSON 规范写入。 | `spine_get_official_spec_summary` | 返回官方文档来源、可写 timeline 字段表和 `4.1.24` 字段适配说明。 |
| 查看这个 JSON 里有哪些动画。 | `spine_get_animations` | 返回 17 个动画及各自时长。 |
| 查看 idle 动画里骨骼 3 的关键帧表。 | `spine_get_animation_sheet` | 返回 `targetName=3` 的 rotate/translate/scale 行。 |
| 查看插槽和默认附件。 | `spine_get_slots` | 返回 slot 绘制顺序、绑定 bone 和默认 attachment。 |
| 校验这个 JSON 是否安全。 | `spine_validate_json` | `ok` 应为 true。 |
| 列出这个文件可恢复的备份。 | `spine_list_backups` | 返回备份列表、hash 和校验结果。 |
| 先 dryRun 恢复这个备份到目标 JSON。 | `spine_restore_backup`，`dryRun:true`，`confirm:true` | 不改变目标文件 hash，返回备份校验结果和将恢复的 hash。 |
| 确认恢复这个备份。 | `spine_restore_backup`，`dryRun:false`，`confirm:true`，传最新 `expectedHash` | 覆盖前生成 `*.before-restore.*.json`，恢复后再调用 `spine_run_validation_pipeline`。 |

## 写入 dryRun 用例

| 自然语言说法 | 期望工具 | 验收点 |
|---|---|---|
| 复制 idle 动画为 test-idle，不要真的写入。 | `spine_clone_animation` | `dryRun=true`，返回 diff 和 summary，原文件 hash 不变。 |
| 新建一个 test 动画，先 dryRun。 | `spine_create_animation` | diff 只涉及 `/animations/test`。 |
| 把 idle 动画里骨骼 3 的 rotate 在 0.25 秒设为 12.5，先 dryRun。 | `spine_set_bone_keyframe` | diff 只涉及 `/animations/idle/bones/3/rotate`。 |
| 把 idle 动画里骨骼 3 的 rotate 写成官方文档里的 angle 字段。 | 不应直接写 JSON；应使用 `spine_set_bone_keyframe` | Agent 应说明当前 `4.1.24` 写入适配字段是 `value`，不是直接自由写入 `angle`。 |
| 把 idle 的 0.5 到 1 秒关键帧整体往后挪 0.2 秒。 | `spine_shift_keyframes` | summary 显示修改数量，operationValidation.ok 为 true。 |
| 把 idle 动画里骨骼 3 的 rotate 幅度整体增加 20%。 | `spine_offset_bone_timeline_values` | 先查表，再对骨骼 3 的 rotate 做 scale。 |
| 让 idle 首尾循环闭合。 | `spine_make_loop` | 把 sourceTime 的已有关键帧复制到 targetTime。 |
| 把 act-run 复制成 test-run，然后把速度加快一倍，先 dryRun。 | `spine_clone_animation` + `spine_scale_keyframe_times` | 先复制，再以 `originTime=0`、`scale=0.5` 缩放时间。 |
| 新建 walktest，做一段 0.6 秒不断走路的循环动画，先 dryRun，不借用现有动画。 | `spine_apply_pose_sequence` | Agent 应先形成姿态时间点计划，再一次性写入 `poses`；`duration=0.6`、`closeLoop=true`，diff 只应落在 `/animations/walktest`。 |
| 根据我的描述凭空制作一个新动作，但不要连续调用很多次单帧写入。 | `spine_apply_pose_sequence` | 复杂姿态序列优先用一次事务；必要时再用 `spine_get_skeleton_hierarchy`、`spine_get_slots` 查询骨骼和插槽名称。 |

## 失败用例

v2 语义流程新增验收用例：

- “这个角色是第一次用，先生成 mapping 草稿”：应调用 `spine_create_mapping_draft`，不得直接真实生成动画。
- “确认角色的左右手脚和脚底点”：应先校准，再调用 `spine_confirm_mapping`，保存确认者和完整 semanticChecks。
- “把参考 walk 提取成可复用动作”：应调用 `spine_extract_motion`，输出 v2 motion 和提取报告。
- “提交刚才通过的动作”：必须传入 dryRun 返回的 `reviewToken` 和 `expectedHash`。
- “使用 draft mapping 直接写动画”：应拒绝。
- “角色已经变化，但继续用旧校准报告”：应拒绝并要求重新校准。
- “目标不可达或脚底误差超阈值仍然写入”：应返回失败报告且不写文件。

| 自然语言说法 | 期望结果 |
|---|---|
| 把关键帧时间改成负数。 | 工具拒绝，提示时间不能为负。 |
| 让 slot 显示不存在的 attachment。 | 工具拒绝，提示 attachment 不存在。 |
| 修改 bones 或 skins。 | 当前 MCP 不提供该写入能力，Agent 应说明不支持。 |
| 平移 slot 的 color timeline。 | 当前 MCP 不支持写入该 timeline，应拒绝并说明只支持 attachment。 |
| 让 Agent 直接打开 JSON 文件手写动画。 | 应拒绝；动画修改必须通过 MCP 写入工具和官方规范审查层。 |
| 对非 `4.1.24` 文件写入。 | 默认拒绝，除非显式传 `allowUnsupportedVersion:true`。 |

## 关节切片工作流用例

- “给这个新角色校准关节”：生成 visualRig 草稿和切片图；未看图和未填写节点依据不能自动批准骨骼原点。
- “按参考分腿准备、双手握持制作”：先确认参考与左右对应，再适配并比较实际节点。旧 NPC1 窄站负例必须失败，即使 IK 误差很小。
- “我批准了，直接保存”：关系 fail/unverifiable 或无新报告时仍拒绝，逐阶段审查不能覆盖程序失败。
- “复用上一轮批准，换一个 skin”：资源指纹改变必须重新校准、出图、比较和审查。
- “把第一阶段换成别的动作，但复用旧报告”：修改目标后旧报告及确认失效。
- “骨架不适配就换姿态”：默认停止并报告，不自动更改动作含义或放宽门限。

验收必须分别记录绑定、关系比较、Agent 视觉、数值/runtime 和编辑器导入；测试绿灯不能描述为视觉一致。

### 右手挥击完整诊断复现

运行 `node scripts/acceptance-right-attack-full.mjs`，读取本轮已修订的上挥、下挥和转身突刺姿态，通过实际 MCP 生成 3.6 秒完整候选、上下同步 GIF、目标原速 GIF、实际动画指定时间图与验收报告。工作区实例目录记录在 `previews/latest-right-attack-full-path.txt`。

右手始终绑定 `ys` 链；水平地面分腿目标不随阶段换链。手腕使用肩部坐标中的弧线轨迹，快速突刺区间增加内部求解采样，最后仍由曲线拟合输出动画时间线。蓄力和收势是制作调整，并非新的已确认参考标注。缺少腿部身份校准及侧背面躯干绑定时必须保留关系失败，不能用数值通过覆盖。脚底、手腕及原文件 hash 分别记录；不批准目标姿态、不生成提交令牌、不修改原角色。

## 完整动画诊断实例（不批准、不提交）

`spine_retarget_motion` 新增 `diagnosticPreview:true`，仅支持 `dryRun`。用户要求观察整段失败候选时，可在保留未确认姿态和失败报告的前提下生成完整诊断动画：候选 JSON、实际关键时间关系比较、固定相机上下姿态图和目标原速 GIF。通过 `spine_render_animation_comparison` 生成上下同步 GIF。

诊断结果始终为 `ok:false`、`diagnosticOnly:true`、`readyToCommit:false`，分别返回 `numericOk`、`poseGate`、`keyGraphs` 和 `previewIssues`，不产生 `reviewToken`，不修改原角色。它是观察失败的独立出口，不能替代正式姿态/动画审查或用于提交。`diagnosticPreview:true,dryRun:false` 必须拒绝；渲染失败仍保留候选与错误。

实际验证脚本：`scripts/acceptance-animation-diagnostic.mjs`。先执行 `references`，Agent 查看参考连线图并填写逐阶段参考判断后执行 `animate`。脚本通过实际 MCP stdio 求解和渲染，仅创建工作流草稿，不自动批准任何目标姿态或完整动画。环境变量 `ANIMATION_DIAGNOSTIC_DIR` 可指定已有实例相对目录。

中文负例：把手目标设到骨骼不可达范围，再请求完整动画诊断。预期得到失败报告及 GIF、原 JSON 哈希未变、无提交令牌；请求真实写入仍应拒绝。不要把 GIF 生成成功描述为动画匹配通过。

## 解剖持杖手、身体视角及切片遮挡检查

参考 observation.actionSemantics 支持 `version:1 / weaponHand:left|right / identityStatus:confirmed / anatomicalBasis / bodyView / bodyViewBasis / occlusion`。身体视角可为 `frontThreeQuarter`、`side`、`backThreeQuarter`，参考有不确定性时可用 `sideOrBackThreeQuarter`。遮挡项保存 `{front,back,basis}`，语义部位可为 `body` 或已有肢体线段编号（如 `rightArm.1`）。缺少必要遮挡关系返回无法验证，不默认为通过。

`spine_calibrate_visual_rig` 增加 `anatomicalSides` 与 `viewProfiles`，均绑定确认指纹。解剖左右映射保持跨阶段稳定；视角配置保存实际附件状态、躯干插槽和看图校准依据。姿态 `frame.action.driver` 明确实际目标驱动手（如 `rightHand`），骨架比较独立输出 `action.weaponHand`、`action.bodyView`、`action.occlusion.*`。身体视角从 runtime 实际附件配置匹配已确认 profile；未经校准不能只传一个“背面”标签通过。遮挡用 runtime 绘制顺序回读。Agent 判断仍参与视角配置校准，这不是自动像素识别或数学上的视觉保证。

`frame.presentation` 支持受控 `attachments` 和完整 `drawOrder` 插槽排列，沿用 `spine_adjust_pose`、`spine_solve_pose` 和 v2 motion。显示状态在阶段边界离散切换，导出为已有 attachment/drawOrder 时间线；不改 setup、绑定、mesh、atlas 或 PNG。现有后发、面部显隐及背包层序可构造转身诊断候选，但不代表有完整三维转身模型。需要逐姿态查看轮廓并重新校准，不能自动批准隐藏五官后的身体视角。

中文验证：右手参考对应左手驱动必须失败；正面配置不能覆盖侧背参考；缺失视角/遮挡信息必须无法验证；同一附件状态不能标记成两种不同视角；遮挡层序反转必须失败。切片状态修改使配置匹配和旧审查失效。官方 runtime 回读 attachment/drawOrder 的阶段切换必须与单姿态一致。

## 准备姿态闭环用例

- “把旧准备姿态和新右手持杖阶段放在一起”：共享动作记录必须报告旧交换对应的 identityConflict。
- “头位置改变，身体是否倾斜”：肩髋躯干轴结果不应改变，头中心连线只作诊断。
- “两脚地面冲突，取平均就好”：分别返回残差，不能平均后批准。
- “绿色指标全通过，直接写入”：仍需独立视觉审查；本轮 npc1 贴脸拳头作为退回实例。
- “修正姿态，沿用上次批准”：保存新修订并使旧比较和审查失效。
- “自动换左右或放宽15°门限”：拒绝，身份、支撑和弯曲分支固定。
- “没有侧背切片，隐藏脸就通过”：返回 resourceCapability，不能批准。
- “默认适配到 dry-retarget.json”：只返回联合修正结果，不产生该文件，不改变角色 hash。

86项测试通过；不同名称和比例角色是合成夹具，不作为真实美术验收。实际 MCP 脚本和输入规范见 [闭环说明](准备姿态适配与修正闭环.md)。
