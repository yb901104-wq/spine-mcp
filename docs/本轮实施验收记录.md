## 2026-10-20 深夜：躯干朝向的求解缺口（用户复核产物图后指出）

### 根因

`retargetReferencePoseSeed` 只做 `frame.body.rotate += delta` 来对齐「髋中心→肩中心」轴。`body.rotate` 同时转动肩线与髋线，**两者夹角（扭转）不变**；`mapping.bones.channels.torso`（npc1 为 bone3）虽然存在于映射里，但种子帧从不写 `frame.channels`。结果是目标肩线朝向永远等于绑定静止姿态，`body.shoulderLine` 与 `body.twist` 在任何姿态下都不可能通过——不是求解不准，是根本没有对应自由度。

### 修复

种子阶段在 `body.rotate` 对齐之后，再按「参考肩线方向 − 当前肩线方向」的差值 `dt` 写入 `frame.channels.torso.rotate += dt` 并重新求解。肩线朝向由躯干通道承担，与髋部朝向解耦。

### 结果（同前一轮参考与姿态参数）

`body.shoulderLine`、`body.twist` 由 fail 转为 pass；干净图上躯干已呈前斜侧，与参考同向。剩余 7 项失败全部集中在手臂：

`arm.left.wristReach` 0.244、`arm.left.wristTorsoHeight` 0.146、`arm.left.wristTorsoOffset` 0.173、`arm.left.wristHeadGap` 0.293、`arm.right.wristHeadGap` 0.284、`leftArm.segment1` 25.69°、`rightArm.wrist` 0.170。

这与上一轮结论一致：参考手位在 npc1 臂长下不可达，求解器只能在折叠与极限伸展之间取折中。躯干已不再是阻塞项。

`npm run build` 通过；`npm test` 92/92 通过。


## 2026-10-20 收尾：对标 3D 软件 MCP 的六项能力补齐

| 项 | 实现 | 实测 |
|---|---|---|

| 单字段编辑 | `spine_set_pose_target`、`spine_set_pose_channel` | 输出新修订并清掉旧求解/审查 |
| 批处理 | `spine_batch_pose_ops`（target/channel/weapon，dryRun 内存摘要，可 render） | 应用 2 个操作后返回失败清单 |

### 两个开关默认关闭的实测原因

- `headFromReference:true`：头部节点在头骨上有偏移，转动头部会同时移动头节点，`arm.left.wristHeadGap` 从 0.293 恶化到 0.611，`leftArm.segment1` 25.7°→28.9°。
- `weaponFromReference:true`：把双手吸附到参考握持轴会把两手推得更远，必要失败从 7 项涨到 15 项（`body.torsoDirection` 也回退到 18.2°）。

结论：这两个自由度确实接上了，但在当前绑定与臂长下与既有指标冲突，只能按阶段显式启用，不能默认开。
