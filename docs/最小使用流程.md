# 最小使用流程

本文档记录 Spine MCP 从 Agent 接入到一次安全写入验证的最短闭环。目标是让用户和 Agent 按同一套步骤工作：自然语言请求从 Agent 发出，MCP 负责写入和审查，WinForms 只负责观察、预览和验证结果展示。

## 角色分工

| 角色 | 负责什么 | 不负责什么 |
|---|---|---|
| 用户 | 提出自然语言需求，确认 dryRun 结果和最终写入。 | 不直接手动改 Spine JSON。 |
| Agent | 理解需求、制定 MCP 调用计划、执行 dryRun、写入和验证。 | 不绕过 MCP 自由编辑 JSON。 |
| MCP | 读取、写入、官方规范审查、diff 白名单、备份、runtime 验证。 | 不判断动画美术质量。 |
| WinForms 观察平台 | 展示连接状态、当前上下文、操作日志、验证结果和预览画面。 | 不作为动画编辑器，不直接写 JSON。 |

## 一次性准备

### 1. 构建项目

在项目根目录执行：

```bash
npm run build
```

如果修改过核心 JSON 操作逻辑，还应执行：

```bash
npm test
```

### 2. 配置 Codex MCP

Codex 配置中加入 MCP server 片段：

```toml
[mcp_servers.spine_json_mcp]
command = 'C:\Program Files\nodejs\node.exe'
args = ['D:\AI_cc\spine-mcp\dist\server.js']
startup_timeout_sec = 30

[mcp_servers.spine_json_mcp.env]
SPINE_MCP_WORKSPACE = 'D:\AI_cc\spine-mcp'
```

配置后需要重启 Codex 或开启新会话，让 MCP 工具重新加载。

### 3. 执行 Agent 握手

Codex 重启并加载 MCP 后，让 Agent 调用：

```json
{
  "tool": "spine_agent_ping",
  "arguments": {
    "clientType": "codex",
    "agentName": "Codex"
  }
}
```

也可以通过以下工具检查状态：

```json
{
  "tool": "spine_agent_get_connection_status",
  "arguments": {
    "clientType": "codex"
  }
}
```

WinForms 中 Agent 连接灯显示为绿色，表示当前 Agent 已经真实连上 MCP。

### 4. 启动观察平台

推荐使用一键脚本：

```bash
npm run observer
```

该命令会构建项目、选择空闲端口、启动浏览器预览服务并打开 WinForms。它只启动观察和验证链路，不写 Spine JSON。

停止观察平台：

```bash
npm run observer:stop
```

## 每次制作动画的推荐流程

### 1. 读取目标文件摘要

先确认目标 JSON 的版本、hash 和可写状态：

```json
{
  "tool": "spine_get_document_summary",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json"
  }
}
```

Agent 应记录返回的 `hash`，后续写入工具通过 `expectedHash` 防止覆盖旧状态。

### 2. 查询动画和关键帧

查看文件里有哪些动画：

```json
{
  "tool": "spine_get_animations",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json"
  }
}
```

如果要修改已有动画，再查询关键帧表格：

```json
{
  "tool": "spine_get_animation_sheet",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "animation": "idle"
  }
}
```

如果要从自然语言凭空生成一段新动画，优先规划成 `spine_apply_pose_sequence` 的多个姿态点，不拆成大量单点关键帧写入。

### 3. 先 dryRun

示例：创建一个 0.6 秒循环走路动画的 dryRun，应使用一次事务写入：

```json
{
  "tool": "spine_apply_pose_sequence",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "animation": "walktest",
    "overwrite": false,
    "duration": 0.6,
    "closeLoop": true,
    "dryRun": true,
    "expectedHash": "<上一步读取到的hash>",
    "poses": [
      {
        "time": 0,
        "bones": {
          "root": {
            "translate": {
              "x": 0,
              "y": 0
            }
          }
        }
      },
      {
        "time": 0.3,
        "bones": {
          "root": {
            "translate": {
              "x": 0,
              "y": 4
            }
          }
        }
      }
    ]
  }
}
```

注意：上面的姿态只是调用格式示例。实际制作动画时，Agent 应先查询骨骼层级和动画目标，再选择真实存在且适合动作的骨骼。

dryRun 后必须检查：

- `summary.wroteFile` 是否为 `false`。
- `affectedPaths` 是否只落在 `/animations/...`。
- `operationValidation.ok` 是否为 `true`。
- `officialSpecValidation.ok` 是否为 `true`。
- `diff` 是否符合用户意图。

### 4. 设置预览会话

dryRun 或写入前后，Agent 可以设置 WinForms 当前观察上下文：

```json
{
  "tool": "spine_preview_set_session",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "atlasPath": "example-json/xiaoren.atlas",
    "animation": "walktest",
    "premultipliedAlpha": true,
    "mipmaps": false,
    "autoload": true,
    "operation": {
      "title": "制作 walktest 循环走路动画",
      "status": "dryRun",
      "detail": "等待用户确认 diff 后写入",
      "toolName": "spine_apply_pose_sequence"
    }
  }
}
```

WinForms 会读取会话状态，刷新当前 JSON、atlas、动画、操作说明、验证结果和预览 URL。

### 5. 用户确认后真实写入

用户确认 dryRun 合理后，Agent 再次读取摘要，拿到最新 `hash`，然后用同一工具提交：

```json
{
  "tool": "spine_apply_pose_sequence",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "animation": "walktest",
    "overwrite": false,
    "duration": 0.6,
    "closeLoop": true,
    "dryRun": false,
    "expectedHash": "<最新hash>",
    "poses": [
      {
        "time": 0,
        "bones": {
          "root": {
            "translate": {
              "x": 0,
              "y": 0
            }
          }
        }
      },
      {
        "time": 0.3,
        "bones": {
          "root": {
            "translate": {
              "x": 0,
              "y": 4
            }
          }
        }
      }
    ]
  }
}
```

真实写入时工具会自动在 `backups/` 中生成备份。实际调用时必须传入和 dryRun 一致的完整 `poses`，不能省略或临时改写姿态内容。

### 6. 写入后验证

写入完成后调用推荐验证流水线：

```json
{
  "tool": "spine_run_validation_pipeline",
  "arguments": {
    "filePath": "example-json/skeleton-4.1.json",
    "atlasPath": "example-json/xiaoren.atlas",
    "animation": "walktest",
    "premultipliedAlpha": true,
    "mipmaps": false,
    "autoload": true
  }
}
```

验证通过后，再在 WinForms 或浏览器预览里观察动作效果。最后仍建议用 Spine 软件真实导入一次，确认官方编辑器可以接受该 JSON。

## 导入失败时的处理

如果 Spine 软件导入失败，不要继续在错误 JSON 上修补。必须按以下顺序处理：

1. 调用 `spine_list_backups` 查找目标文件最近备份。
2. 选择最近一次确认可导入的备份。
3. 调用 `spine_restore_backup`，先 `dryRun:true`。
4. 确认后调用 `spine_restore_backup`，传 `dryRun:false`、`confirm:true` 和最新 `expectedHash`。
5. 恢复后调用 `spine_run_validation_pipeline`。
6. 在恢复后的 JSON 上重新制作目标动画。
7. 将失败原因补进测试或官方规范审查文档。

## 自然语言请求模板

用户可以直接对 Agent 这样说：

```text
给 example-json/skeleton-4.1.json 新建一个 walktest 动画，做 0.6 秒循环走路动画，先 dryRun，不借用现有动画。
```

Agent 应执行：

1. 查询 `spine_get_document_summary`。
2. 查询骨骼、插槽或必要动画信息。
3. 形成 `spine_apply_pose_sequence` 调用计划。
4. 执行 `dryRun:true`。
5. 向用户说明会修改哪些 `/animations/...` path、官方规范审查是否通过、是否需要写入。

用户确认后可以继续说：

```text
写入，并执行验证流水线。
```

Agent 应重新读取最新 hash，执行 `dryRun:false`，然后调用 `spine_run_validation_pipeline`，并更新 `spine_preview_set_session`。

## 关键原则

- 所有真实修改都必须由 MCP 写工具完成。
- 所有写工具先 dryRun，再确认写入。
- 复杂新动画优先使用 `spine_apply_pose_sequence` 一次事务。
- 写入前后都要使用 `expectedHash`。
- WinForms 只观察，不作为操作主体。
- Spine 导入失败时先恢复备份，再重新制作。
