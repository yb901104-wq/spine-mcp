# 细节工具实测验收（2026-10-09）

## 可重复运行的脚本

在项目目录运行，顺序执行：

```powershell
npm run build
node scripts/acceptance-detail-tools.mjs
node scripts/acceptance-walk-details.mjs
node scripts/acceptance-preview.mjs
npm test
```

脚本通过 SDK stdio 客户端调用真实 MCP Server。数据来自 `D:/AI_cc/spine test`，输出写入 `previews/验收优化-20261009`。原角色与旧输出不修改。idle 脚本会重新复制输入；walk 脚本保留独立测试副本，重复运行只允许覆盖其测试动画。实际 walk 实测显式 preview:false 分离数值过程，随后运行预览脚本生成视觉对比；不能将该步骤称作默认完整预览流水线验收。

优化输出与 7954 帧关键数据的稠密参考比较，采用 1335 个时间点官方 runtime 回读，首尾世界姿态误差为 0。关键帧减少约 73.8%，仍使用补间。旧结果和新结果使用同一固定镜头输出动图。

## walk 调整验证

测试六种中层工具：脚目标、脚接触、手目标、身体起伏、步幅和手臂摆幅。每次调整保存新 motion，然后执行重定向 dryRun；通过后使用 expectedHash/reviewToken 写入测试副本。不能把“成功修改 motion”当作“最终动画通过”。脚接触锁定目前作用于指定主要姿态，不是完整时间区间。

验收脚本保持脚底 0.001、手腕 0.1、旋转 0.3°、位移 0.07、顶点 1.2 的门槛。参考动作提取会把支撑姿态及离地首姿态的 y 标准化到地面，以避免阶段边界出现高度跳变。求解保留脚底最低顶点切换的姿态，压缩重试同时检查末端接触和手腕误差，不通过时仍拒绝提交。

完整调用参数、成功或失败报告保存为 `walk-tool-calls/*.json`，汇总为 `walk-acceptance.json`。故意设置不可达目标必须失败，且角色文件不能出现 `should-not-write` 动画。对比 GIF 的 manifest 保存两组帧产物和固定镜头范围。

## 验收范围

本轮实际 MCP 六工具均通过（脚目标、已有支撑姿态的脚锁定、手目标、bodyBob=0.001、步幅×1.01、手臂摆幅×1.03），每个输出完成 dryRun 和 hash/token 提交。walk 基线及六变体在 337 点 runtime 采样下最大脚底误差不超过 0.000450，最大手腕误差不超过 0.000219，首尾误差为 0。不可达手目标被拒绝，原有动画和角色数据保留。指定脚锁定的测试是已有支撑姿态回归，不证明任意腾空姿态可直接落地。walk 结果与旧 Python 的 8.38e-7 地面指标采用不同坐标和采样，不能据此声称已优于旧 walk。

构建及 58 项回归测试通过。walk 曲线统计示例：64554 个稠密求解关键帧压缩为 4898 个关键帧，减少约 92.4%；严格接触门槛触发五轮拟合重试。当前角色的一整轮实测需要数分钟，后续可优化 dryRun/commit 计算复用。

数值、官方 4.1.x runtime、MCP 写入门禁和离线视觉产物可以自动验证。Spine 编辑器实际导入仍需单独验收；runtime 加载成功不代替编辑器导入成功。
