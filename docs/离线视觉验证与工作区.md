# 离线视觉验证与工作区使用

## 标准流程

1. 优先让客户端提供 MCP Roots；服务自动登记 file URI 并生成 projectId。客户端不提供 Roots 时保留 SPINE_MCP_WORKSPACE 或启动目录作为兼容工作区。
2. 用 spine_list_workspaces / spine_get_workspace_info 查看实际项目。多项目任务显式传 projectId，避免依赖活动项目。
3. 角色 mapping 必须经过校准、确认；spine_retarget_motion 默认 dryRun:true、preview:true。
4. dryRun 返回数值报告、reviewToken、报告路径和 contact sheet。Agent 查看图片；调整 motion 后重新 dryRun。
5. 使用同一 expectedHash、reviewToken 提交；MCP 再次计算并执行门禁、角色文件锁、备份和 diff 白名单。
6. 需要动态检查时调用 spine_render_animation_gif；局部放大使用 bounds。正常任务只生成报告和联系图。

## 预览工具

| 工具 | 输出 |
|---|---|
| spine_render_animation_frames | PNG 帧、固定相机 bounds、角色轨迹 manifest |
| spine_render_contact_sheet | 最多12个代表姿态组成的 PNG 联系图 |
| spine_render_animation_gif | 本地编码的 GIF，复用帧缓存 |
| spine_create_preview_manifest | JSON、atlas、全部贴图、mapping、motion hash 以及渲染参数 |
| spine_get_preview_report | 默认摘要；detailed:true 返回完整轨迹 |
| spine_compare_animation_previews | 按周期对应的并排图、首帧叠加图、归一化锚点误差和运动范围；pixelComparison:true 需相同贴图、相同 bounds，输出首帧差异图 |
| spine_analyze_reference_gif | 合成 disposal 帧、读取/补正延迟、重复帧、画布范围、循环扩展、参考 manifest |
| spine_extract_reference_keyframes | 去重复后均匀选取代表帧；阶段采用 Agent 的 phases 标注 |

不同角色的运动比较需要分别提供 mappingPath。body/head 和脚底/手腕锚点按校准 scale、origin 归一化。起点相位由 Agent 确认；GIF 没有骨骼语义，因此与角色比较只能提供图像证据和节奏，不产生精确 IK 数据。GIF 总时长是周期估计，不能自动保证它包含完整循环，也不能自动分离相机与角色移动。

默认选择：有可见默认皮肤时使用默认；默认皮肤没有可见附件时选首个带可见附件的皮肤并在 manifest 明示。正式生产建议始终指定 skin。

## 工作区工具

| 工具 | 行为 |
|---|---|
| spine_list_workspaces | 查看全部登记项目和活动项目 |
| spine_register_workspace | rootPath 登记并生成或指定 projectId；同一个 projectId 不能改绑另一目录 |
| spine_get_workspace_info | 查询工作区路径和来源 |
| spine_select_workspace | 选择已登记工作区 |

全部现有 MCP 工具均接受可选 projectId。调用使用异步局部上下文，因此并发任务不会互相改工作区。项目数据、备份、报告、session 位于项目内；服务程序、网页和 vendor 仍从 MCP 安装目录加载。所有路径拒绝越界与符号链接逃逸。注册操作本身可以指定新项目根目录，普通资源工具不能访问未登记的其他根目录。

浏览器 URL 包含 projectId；资源通过 /projects/<projectId>/workspace/... 读取。WinForms 继续读取 session 和 previewUrl，不静默修改全局 Agent 配置。

## 缓存与失败报告

previews/cache/<cacheKey> 存放共享不可变 PNG 帧；previews/jobs/<jobId> 存放该任务 manifest/status；previews/reports 保存数值报告、比较和批处理结果。缓存键包含全部输入 hash 和渲染参数，改贴图也会失效。成功与失败任务均保留状态。资源文件不写入 Git。

相同缓存的并发生成会报告忙，请稍后重试。角色写入使用 .spine-mcp/locks 文件锁；锁中记录 pid。进程意外终止留下的锁应确认进程已退出后再清理，不能直接抢占运行任务。

## 局部调整

spine_set_foot_target、spine_lock_foot_contact、spine_set_hand_target、spine_adjust_body_motion、spine_adjust_step_length、spine_adjust_arm_swing 修改 v2 motion，默认 dryRun。使用新的 outputMotionPath 保留原动作；再重定向自动重算 IK、约束与曲线。目标坐标为 normalizedSkeleton，time 对应已有主要姿态。factor 用于水平步幅或手腕摆幅比例。

## 当前边界

Canvas 渲染支持 region、mesh、普通 clipping、颜色/Alpha 和常见混合模式；双色 tint、嵌套 clipping 会明确拒绝并建议官方浏览器预览。离线不使用 mipmaps。GIF 阶段不会自动识别为可靠接触事件。Spine 编辑器导入仍须人工验证，本次没有操纵编辑器或声明编辑器已通过。

旧项目的 Python 数值回归与官方 runtime 数值必须分开：idle 的旧 Python 旋转误差0.3011°，官方 runtime 实测0.4094°；后者没有满足0.35°，不能宣称该门槛已通过。新生成动画仍按自身 runtime 误差门禁处理。
