## 2026-11-03 参考链路：帧回传、叠加对比与按需取帧（已实施）

## 2026-11-03 curve 维度校验与点状骨骼透视方案

### curve 控制点维度校验（已实施，提交 `35af807`）

对照用户提供的[官方 JSON 格式文档](https://zh.esotericsoftware.com/spine-json-format)时发现两个层次的问题。

**层次一：官方文档是 3.8 口径，不能作写入校验依据。** 实测与 4.1.24 至少三处硬冲突：`rotate` 字段文档写 `angle`、runtime 实际只读 `value`；绘制顺序 timeline 名文档写全小写 `draworder`、runtime 实际读 `map.drawOrder`；curve 的 X 轴文档写"单位是帧"、runtime 实际为 0..1 归一化。项目在这三处原本就以 runtime 为准，未盲信文档。据此在 [官方 JSON 规范审查](官方JSON规范审查.md) 中重申：官方文档只作字段语义参考，最终判定依据是 4.1 runtime 源码与当前版本真实样本。

**层次二：官方文档完全没写的维度约束。** `readCurve()` 中 `let i = value << 2` 表明控制点数组按维度排列，二维 timeline 还要读 `curve[4..7]`。实测把 `bone2.translate` 的 6 个 8 元 curve 截成 4 元后，官方 runtime 采样 41 帧中**40 帧 y 为 NaN，x 完全正常且不报错**——静默污染，视觉上只是单方向抽动，极难回溯。

已加规则：rotate 恰好 4 个、translate/scale/shear 恰好 8 个，长度不符报 `VALIDATION_FAILED` 拒绝，不自动补全控制点；pose 级 curve 同时覆盖维度需求不一致的 timeline 时拒绝。`test/spineJson.test.ts` 单跑 45/45，curve 相关四个文件 29 通过 0 失败，MCP stdio 端到端 7 组用例符合预期。未增删任何 MCP 工具。

> 回归口径修正：全量 `npm test` 会稳定失败 25 项，全部是宿主 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`（单轮累计删除超阈值 50），集中在 `spineJson.test.ts` 的 `beforeEach` 反复 `rm(test-output)`，与代码无关。**回归以分文件跑为准**，不再以全量数字判断。

### 点状骨骼位移透视方案（未实施）

用户提出真人 2D 骨骼动画的工业做法：每段肢体末端挂点状子骨骼，下一段绑定其下，mesh 同时绑定该段骨骼与末端点状骨骼做平滑权重过渡，**用点状骨骼的位移而非缩放**制造空间透视。

这直接消掉现有 scale 方案的两个结构性缺口：位移不传递缩放，因此不污染子骨骼；IK 使用 `bone.length` 不读 scale，因此可共存。且公式可闭式化为 `L′ = L·cos θ`、`Δ = L(1−cos θ)`，替代当前会 `localStall` 的迭代求解。

关键决策：**不突破 `AGENTS.md:26` 的 V1 边界**——MCP 不自建点状骨骼、不刷 mesh 权重，改为"资产前置条件 + 只读校验 + 只写 translate 关键帧"。与现有 scale 方案**并存但严格互斥**，不废弃 npc1 0.85–1 的既有批准与证据。

§7 已就五项未解决项给出建议，其中两项是要点：IK 共存采用"施加位移期间该段不使用 IK"（先位移再解 IK 会被覆盖、折算进 IK 目标会导致屈肘，均不可取），且**默认拒绝、不提供自动 bypass**；取得满足条件的真实角色设为实施前置门槛，在此之前不写实现代码。

当前样本 `example-json/xiaoren.json` 皮肤附件**只有 region、无 mesh**，不满足前置条件，方案尚未在任何真实角色上跑通。

| 环节 | 事实 |

| 现象 | `client.rpc(..., control=true)` 得到服务端 `CONTROL_REQUIRED`，24 项失败 + 14 项断言语义差异 |
